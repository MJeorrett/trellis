# Capability: Examples

## User Need
As a Trellis author (human or AI agent), I want a page of working examples that shows every element and feature of the wire frame syntax, with notes explaining each one, so that I can learn the syntax and copy an example without reading the capability files.

## Product Decisions
* **[2026-11-23] CI-023 Examples page (planned):** A new top nav item, `Examples`, opens the `/examples` page (see `CI-023 Examples nav item (planned)` in the `features` capability). The page has an `Examples` heading followed by one section per example, in a fixed order. It is read-only and holds no user data: nothing on it can be edited or saved, and it looks the same on every visit. It is not part of any feature and does not change features, macros or the data dictionary.
* **[2026-11-23] CI-023 Example section (planned):** Each example is a section with a heading (the name of the element or feature), the example's source as read-only monospace text on the left and the wire frame that the source compiles to on the right (the same preview, page tabs, links and sketchy look as a feature's wire frame), stacked one above the other on a narrow window. The notes explaining the example are written in the source itself as comments (see `CI-023 Comments (planned)` in the `trellis-ast` capability), so the shown source is annotated and exactly what is compiled. A section that has an error shows the message in place of the preview, so a broken example is visible rather than hidden.
* **[2026-11-23] CI-023 Coverage (planned):** There is at least one example for every element and every feature of the syntax, each small and focused on one thing, in this order. (4) Data references: a pointer (`@User.FirstName.label`), a pointer in a macro argument and a pointer `TableColumn`. (5) Comments. The page does not wait for the user's macros or data dictionary to load.

* **[2026-11-25] CI-027 Syntax summary (planned):** Under the `Examples` heading and before the first example, the page shows a `How Trellis syntax works` section: a numbered list of short rules, written for someone who has never seen the syntax, covering what the examples do not say on their own. (1) The pipeline: macros are expanded first, then the core syntax is parsed, then pointers are resolved against the data dictionary, then the wire frame is drawn, and the wire frame source and the data dictionary are separate texts. (2) Structure: one node per line as `Type "text" attributes`, nesting by exactly 2 spaces per level, no tabs, a source is one or more `Page "Title" id=...` lines at indent 0 and nothing else is allowed at indent 0 except `Def` and comments, and a `Page` is never nested. (3) Text and tokens: text is always in double quotes with no escapes (so it cannot contain `"`), tokens are separated by exactly one space, attributes come after the text in any order and each at most once, and which types take which attributes (`link-to`, `width`, `font`, `font-size`, `aspect-ratio`, `id`). (4) Layout: `Row` and `BoxRow` lay children on one non-wrapping line, `width` is a number of twelfths of the parent row, a `Spacer` is only valid directly inside a `Row` or `BoxRow`, and a `Table` holds only `TableColumn`s. (5) Macros: a `Def` is written at indent 0 above its first use, its body is core syntax with `$param` anywhere on a line (the body writes its own quotes), and a use is `Name key=value`. (6) Data references: a bare `@Entity.Field` is a pointer into the data dictionary and quotes always make a literal. (7) Comments: a line that starts with `#` in column 0. (8) Errors: the parser stops at the first error and reports `Line <n>:` counted in the source as written, so fix the first error and check again. (9) How to work: find the closest example below, copy its source and change it, rather than writing from memory. The summary is part of the page, in the same fixed text on every visit, and is not an example (it has no source or preview).
* **[2026-11-25] CI-027 Copy for agents (planned):** A `Copy for agents` button in the header row of the page, at the right end of the `Examples` heading's row, copies the whole page as one markdown text to the clipboard and shows a `Copied for agents` success toast; if the clipboard write fails an error toast says so. The previews are not part of it. It is plain markdown that stands on its own, so it can be pasted into a prompt, `AGENTS.md` or a rule file. The text is built from the same data the page shows (summary, `examples` and `exampleDataDictionary`), so the page and the copy cannot differ.

## Technical Decisions
* **[2026-11-23] CI-023 Examples data (planned):** The examples are plain data in `src/web/examples/examples.ts`: `exampleDataDictionary: DataDictionaryRow[]` and `examples: Example[]` with `Example = { title: string; source: string }`, where `source` is wire frame syntax including its comments, written as template strings. Keeping them as source text (not parsed ASTs) means the page shows exactly what is compiled. A small Zod schema (`ExampleSchema`, `z.strictObject({ title: z.string().min(1), source: z.string() })`) validates the list, and the types are derived with `z.infer`, as elsewhere in the project.
* **[2026-11-23] CI-023 Compilation (planned):** Each example is compiled with the existing `compileSyntax(source, undefined, exampleDataDictionary)` (no shared macros, the built-in dictionary), so the page adds no syntax logic. The compile is memoised per example. The preview reuses `PageTabs` with the same `onLink` handling as `WireframeEditor`, and the source is shown in a read-only `Textarea` or `pre` (selectable, scrolling horizontally if needed). A shared preview piece may be extracted from `WireframeEditor` if that avoids duplication, without changing its behaviour.
* **[2026-11-23] CI-023 Page and route (planned):** `ExamplesPage` lives in `src/web/pages/examples.tsx` (with `ExamplesView` for static rendering, as the Macros page has `MacrosView`), its path is `EXAMPLES_PATH` (`/examples`) in `appRoutes`, and the nav item is added to `navItems`. The page scrolls inside the routed content area like the features list (it does not use the static window-filling layout of the details page). Tests use `renderToStaticMarkup`, as in the rest of the project.
* **[2026-11-23] CI-023 Examples stay valid (planned):** A test compiles every example and fails if any has an error, so an example cannot silently rot when the syntax changes. Another checks that the examples collectively use every node type in `NodeTypeSchema.options`, so adding a type forces adding an example.
* **[2026-11-23] CI-023 Examples implementation (technical):** The `(planned)` Examples data, Compilation, Page and route and Examples stay valid decisions are confirmed as implemented. (1) `src/web/examples/examples.ts` exports `ExampleSchema`, `Example`, `exampleDataDictionary` and `examples` (parsed through `z.array(ExampleSchema)` at load, so a malformed entry fails at once). (2) `ExamplesView` (props `examples` and `dataDictionary`, defaulting to the built-in ones, so a test can pass a deliberately broken example) and the default export `ExamplesPage` are in `src/web/pages/examples.tsx`; each `ExampleSection` memoises `compileSyntax(source, undefined, dataDictionary)` and keeps its own selected page tab for `PageTabs`, which handles links and the not-found toast itself, so no `WireframeEditor` code was extracted or changed. (3) `EXAMPLES_PATH` (`/examples`) is in `appRoutes` and `Examples` is in `navItems` after `Macros`. (4) Tests: `examples.test.ts` (every example compiles against the built-in dictionary, titles unique, each has a comment, together they use every `NodeTypeSchema.options` type), `src/web/pages/examples.test.tsx` and the nav and route checks in `features.test.tsx`.
* **[2026-11-25] CI-027 Summary data (planned):** The summary is plain data in a new `src/web/examples/summary.ts`, next to the examples: `syntaxSummary: SyntaxSummary` with `SyntaxSummary = { heading: string; rules: string[] }`, validated at load with a Zod schema (`SyntaxSummarySchema`, a `z.strictObject({ heading: z.string().min(1), rules: z.array(z.string().min(1)).min(1) })`, type derived with `z.infer`), as `examples.ts` does. A rule is a plain sentence or two, with inline code written in backticks; the page shows it as text with the backtick parts in a monospace `code` element, using one small pure helper (`splitInlineCode(text): { code: boolean; text: string }[]`), so no markdown library is added. The same string is copied verbatim into the markdown.
* **[2026-11-25] CI-027 Markdown builder (planned):** A pure, DOM-free `buildAgentMarkdown(summary, examples, dataDictionary): string` in `src/web/examples/markdown.ts` builds the copied text as described in `CI-027 Copy for agents (planned)` (summary rules as `1.`, `2.`, ... lines; each example source in a fence that is longer than any run of backticks in the source; the dictionary as a table with `|` in a cell escaped as `\|`; ends with one newline). `ExamplesView` takes an optional `summary` prop (default `syntaxSummary`) next to its `examples` and `dataDictionary`, and the button calls `navigator.clipboard.writeText(buildAgentMarkdown(...))` and `toast` from `sonner`, as the share link does. The button is the existing shadcn `button`; no dependency is added.

Another checks that `buildAgentMarkdown` contains every example's title and exact source and every summary rule, and that its code fences are balanced. The existing examples tests (every example compiles, every type used) are unchanged and still guard the examples themselves.

## Data Dictionary
- `Example`: One entry of the Examples page, UI-only and never stored: `title` (the section heading, non-empty) and `source` (annotated wire frame source, including comment lines).
- `SyntaxSummary`: The written summary at the top of the text `Copy for agents` copies (not shown on the page), UI-only and never stored: `heading` (non-empty) and `rules` (a non-empty list of non-empty strings, each a short rule that may use backticks for inline code).
- `Agent markdown`: The text `Copy for agents` copies, built by `buildAgentMarkdown` from the summary, the examples and the example data dictionary. UI-only, never stored.
- `exampleDataDictionary`: The fixed list of `DataDictionaryRow`s the examples' pointers are resolved against. It is part of the app, not user data, and is shown read-only on the Examples page.
