# Capability: Share Link

## User Need
As a Trellis user, I want to create a link to the wire frames of a feature, with its data dictionary, so that someone else can view them without needing my data or seeing the source.

## Product Decisions
* **[2026-11-25] CI-026 Share button (planned):** The feature details page header has a `Share link` button, at the right end next to `Back to features`. Clicking it copies a link to the clipboard and shows a success toast (`Link copied`). If the clipboard cannot be written, the toast is an error that shows the link so it can be copied by hand. The button is not shown on the `Feature not found` page.
* **[2026-11-25] CI-026 Shared page (planned):** The link opens a read-only page at `/share`. It shows the feature's name as a heading, one tab per page of the wire frame (named and behaving as the "Wire frame" card's page tabs do: rendered preview, links between pages, the not-found toast, the sketchy look) and, at the bottom, the data dictionary as a read-only table (`Entity`, `Field`, `DataType`, `Label`, `MockValues`). It never shows the wire frame source, a source editor, any editing control, the macros, or anything that saves data. A wire frame with a syntax error shows its message in place of the preview, as on the Examples page.
* **[2026-11-25] CI-026 Shared page chrome (planned):** The shared page does not have the app's top nav. It has a simple top bar with a visible `Trellis` link on the left that opens the app (`/features`), and a footer reading `Shared by Trellis` where `Trellis` is also a link to the app. The data dictionary is pinned at the bottom above the footer, like on the details page; the page tabs and preview scroll in the middle.
* **[2026-11-25] CI-026 Snapshot (planned):** The link is a snapshot, not a live view: it holds the feature's name, its wire frame source, the global macros source and the data dictionary as they were when the link was created. Later edits in the app do not change a link that was already shared, and the recipient's own data is never used or changed. The global macros are included so wire frames that use them render the same; they are used to compile the wire frame but are not shown.
* **[2026-11-25] CI-026 Invalid link (planned):** A `/share` link with no data, or data that cannot be read (cut off, edited, not a Trellis link), shows the message `This link is not valid` with the `Trellis` link, and nothing else.
* **[2026-11-25] CI-026 Not in this iteration (planned):** Left for later: a short or revocable link (there is no backend), a password, picking a subset of pages, a copy-to-my-features button on the shared page, and a link to a single page.

## Technical Decisions
* **[2026-11-25] CI-026 Data in the URL hash (planned):** The data is stored in the URL's hash, `/share#d=<data>`, so it is never sent to a server and needs no backend, and the link works on the existing single-page hosting (`public/_redirects` already serves `/share`). The shared data is `{ v: 1, name, wireframe, macros, dataDictionary }`, defined with Zod in `src/web/share/schema.ts` (`SharedWireframeSchema`, a `z.strictObject`, with `dataDictionary` using `DataDictionaryRowSchema`) and its type derived with `z.infer`. The `v` field is the format version so the format can change later without breaking old links.
* **[2026-11-25] CI-026 Encoding (planned):** The data is serialised as JSON, compressed with the browser's built-in `CompressionStream("deflate-raw")` and written as base64url, so no dependency is added and typical links stay short. Decoding reverses this with `DecompressionStream` and validates the result with `SharedWireframeSchema`. The pure, DOM-free parts live in `src/web/share/encode.ts` (`encodeShare(data): Promise<string>` and `decodeShare(text): Promise<SharedWireframe | undefined>`, which returns `undefined` for anything invalid) so they can be tested without a DOM. `buildShareUrl(origin, data)` returns the full link.
* **[2026-11-25] CI-026 Length warning (planned):** Browsers accept very long hash URLs, but chat and email tools may cut them off. When the link is longer than `MAX_SHARE_URL_LENGTH` (30,000 characters, an exported constant) the link is still copied, but the toast warns that it is long and may be cut off by some tools.
* **[2026-11-25] CI-026 Page and route (planned):** `SharedPage` (`src/web/pages/shared.tsx`, with `SharedView` taking the decoded data for static rendering) reads `location.hash`, decodes it in an effect and compiles the wire frame with `compileSyntax(wireframe, macros, dataDictionary)`, reusing `PageTabs` as the Examples page does. `SHARE_PATH` (`/share`) is added to `appRoutes`. `App` does not render `TopNav` on `/share`; the shared page renders its own bar and footer. The data dictionary table is the same read-only table the Examples page uses, extracted to a shared component only if that does not change that page's behaviour.
* **[2026-11-25] CI-026 Button (planned):** The `Share link` button lives in `FeatureDetailsView` (`src/web/pages/feature-details.tsx`), which takes an optional `onShare` callback like its other callbacks; `FeatureDetailsLoader` builds the data from its state (feature, macros, data dictionary), calls `buildShareUrl` and `navigator.clipboard.writeText`, and shows the toast with `sonner`.
* **[2026-11-25] CI-026 Implementation:** The `(planned)` Data in the URL hash, Encoding, Length warning, Page and route and Button decisions are confirmed as implemented, with these clarifications. (1) `buildShareUrl` is async (it returns `Promise<string>`) because compression is. (2) `SHARE_PATH` and `MAX_SHARE_URL_LENGTH` are defined in `src/web/share/encode.ts` (so the encoding module does not import the pages) and `App.tsx` re-exports `SHARE_PATH` and adds it to `appRoutes`. `encode.ts` also exports the pure `isShareUrlTooLong(url)` and `shareDataFromHash(hash)` (`#d=<data>` to `<data>`, `""` for anything else). (3) `decodeShare` returns `undefined` for anything that is not base64url, cannot be inflated, is not valid UTF-8 or JSON, or does not match `SharedWireframeSchema` (so also an unknown key or another `v`). (4) `SharedPage` reads the hash with `useLocation()` and decodes it in an effect; until then it shows only the bar and footer. `SharedFrame` (the bar and footer, exported), `SharedView` and `InvalidShareView` live in `src/web/pages/shared.tsx`, the latter two each wrapped in the frame. (5) `App` hides `TopNav` when `matchPath(SHARE_PATH, pathname)` matches, so `/share/` does too. (6) The read-only table was extracted from the Examples page, with identical markup, to `DataDictionaryTable` (`src/web/data-dictionary/data-dictionary-table.tsx`); the shared page wraps it in a `Data dictionary` section. (7) `FeatureDetailsView` shows `Share link` (an outline small `Button`) just left of `Back to features`, both in a right-aligned group, only when `onShare` is given; without it the header is unchanged. (8) `FeatureDetailsLoader` shows `Link copied` (`toast.success`), `Link copied, but it is long and may be cut off by some tools` (`toast.warning`) or, if `navigator.clipboard.writeText` fails, `toast.error` with `The link could not be copied. Copy it by hand: <link>`. (9) Checked in a browser: the link opened in a session with cleared local storage showed the name, the tabs and the dictionary, links between pages switched tabs, and `/share#d=garbage` showed `This link is not valid`; the clipboard write was denied in that browser, which exercised the error toast. (10) Fixed a type error in `src/web/syntax/parse.test.ts` (an untyped tuple list) that made `pnpm typecheck` fail before this iteration.

## Data Dictionary
- `SharedWireframe`: The data inside a share link, UI-only and never stored: `v` (format version, `1`), `name` (the feature's name, string), `wireframe` (the feature's wire frame source, string), `macros` (the global macros source, string, may be `""`) and `dataDictionary` (a list of `DataDictionaryRow`, see the `data-dictionary` capability).
- `MAX_SHARE_URL_LENGTH`: The length above which the copied link gets a warning (30,000 characters).
