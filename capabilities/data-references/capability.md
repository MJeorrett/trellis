# Capability: Data References

## User Need
As a Trellis author (human or AI agent), I want to point at a field of the data dictionary from a wire frame (`Text @User.FirstName.label`) instead of retyping its label or sample value, so that the wire frame and the data dictionary stay in step and I only describe the data once.

## Product Decisions
* **[2026-11-23] CI-020 Two files, three stages (planned):** UI structure and data stay separate: the wire frame source (core syntax plus macros) and the data dictionary (see the `data-dictionary` capability) are never merged into one text. A data reference, written with `@`, joins them in the last stage. The pipeline is: raw source, macro preprocessor (`macros`; expands `Def`s, does not read or validate the data dictionary, and passes `@` references through), core parser (`parseSyntax`; tells a quoted literal from an unquoted reference and checks only the shape of the reference), symbol resolver (new; checks each reference against the data dictionary and replaces it with the field's value), renderer. The renderer and the viewer only ever see resolved text. The core primitives (`Page`, `Row`, `BoxRow`, `Box`, `Text`, `Image`, `Spacer`) are unchanged.
* **[2026-11-23] CI-020 Pointer syntax (planned):** A pointer starts with `@` followed by Pascal case names separated by `.`, with no spaces. This iteration supports field pointers: `@User.FirstName` (the field's mock value), `@User.FirstName.mock` (the same, written out) and `@User.FirstName.label` (the field's label). `Entity` and `Field` are the names used in the data dictionary (see `CI-016 Pascal case (planned)`) and are case-sensitive; the last part, `label` or `mock`, is lower case. An entity pointer (`@User`, the entity as a whole) is reserved for later and is an error for now (see `CI-020 Errors (planned)`).
* **[2026-11-23] CI-020 Literals and pointers (planned):** Hardcoded text is always in double quotes (`Text "Work Email"`) and a data reference is never quoted (`Text @User.FirstName.label`). Quotes always make a literal: `Text "@User.FirstName"` shows the characters `@User.FirstName`. A pointer can be used wherever a node's text can be written, that is, on `Box`, `Text`, `Row` and `BoxRow`, in place of the quoted string and followed by the same attributes (`Text @User.FirstName.label font=bold`). A `Page` title stays a quoted literal, and `Spacer` and `Image` still cannot have text. This amends the `trellis-ast` rule that bare unquoted text is an error: unquoted text that is a valid pointer is now allowed, any other unquoted text is still an error.
* **[2026-11-23] CI-020 Resolution (planned):** `@Entity.Field.label` shows the `label` of the data dictionary row with that entity and field, and `@Entity.Field` or `@Entity.Field.mock` shows its `mockValue` (an empty label or mock value shows as empty text). If the data dictionary has the same entity and field twice, the first of those rows is used. The spec's per-entity list of mock records (`User.mocks[0]`) does not exist yet: the single `mockValue` of a field is the mock value for now. The resolved text replaces the pointer, so everything else about the node (attributes, link, width, font) is unchanged.
* **[2026-11-23] CI-020 Errors (planned):** Like all syntax errors they are fail-fast, with the 1-based line number of the source as written (a pointer that came from a macro is reported at the line that uses the macro, with the macro named, as in `CI-017 Error lines (planned)`), prefixed `Line <n>: `. From the core parser: `Invalid pointer "<token>" (expected @Entity.Field, @Entity.Field.label or @Entity.Field.mock)` for a malformed pointer (a name that is not Pascal case, an empty part, a suffix other than `label` or `mock`, or more parts than that), and `Pointer "<token>" must name a field (expected @Entity.Field)` for an entity pointer such as `@User`. From the resolver: `Unknown entity "<Entity>"` when no row has that entity, and `Unknown field "<Entity>.<Field>"` when the entity exists but has no such field. The preview shows `Fix the source to see the wire frame.` while there is an error, as for any other syntax error.
* **[2026-11-23] CI-020 Live preview (planned):** The preview of a feature's wire frame and the preview on the Macros page resolve pointers against the data dictionary, so an edit to the dictionary (a label, a mock value, an added or renamed field) is reflected in the preview straight away on the feature page, and on the Macros page the next time it is opened. Both pages wait for the data dictionary to load before showing their editor, so a pointer never flashes as an error. A source without pointers behaves exactly as before.
* **[2026-11-23] CI-020 Pointer arguments for macros (planned):** A macro argument can be a pointer. A bare argument value that starts with `@` is a pointer (`Field field=@User.FirstName`) and must be a valid pointer, otherwise `Invalid pointer "<token>" ...` as above; a quoted value is always a literal, so a literal that starts with `@` must be quoted (`label="@home"`). This changes bare values that started with `@`, which used to be literals. The preprocessor does not look the pointer up. (1) For a plain parameter (`Def Label $text`) the pointer is the value: the body's `$text` becomes `@User.FirstName`. (2) For an object parameter (`Def Field $field=label|mockValue`) a pointer argument `field=@User.FirstName` fills each declared field from the dictionary column of the same name: `$field.label` becomes `@User.FirstName.label` and `$field.mockValue` becomes `@User.FirstName.mock`. In this iteration the only fields allowed for a pointer argument are `label` and `mockValue`; any other declared field is `Field "<field>" of parameter "$<name>" cannot be filled from @<Entity>.<Field> (expected label or mockValue)`. A pointer argument for an object parameter must name a field (an entity pointer is `Pointer "<token>" must name a field (expected @Entity.Field)`), and the piped form (`item="Hi"|"Text"`) is unchanged and always literal. (3) When a placeholder that is replaced by a pointer is the whole content of a quoted string in the body, the quotes are dropped: `Text "$field.label"` expands to `Text @User.FirstName.label` and `Box "$field.mockValue"` to `Box @User.FirstName`. A placeholder with other text around it inside quotes (`"Name: $field.label"`) stays a literal and shows the pointer's characters, because quotes make a literal. Literal arguments expand exactly as before.
* **[2026-11-23] CI-020 Example (planned):** With `Def Field $field=label|mockValue` whose body is `Text "$field.label"` and `Box "$field.mockValue"`, and a data dictionary row `User`, `FirstName`, label `First Name`, mock value `Jane`, the line `Field field=@User.FirstName` expands to `Text @User.FirstName.label` and `Box @User.FirstName`, which resolve to `Text "First Name"` and `Box "Jane"`.
* **[2026-11-23] CI-020 Any column (planned):** This amends `CI-020 Pointer syntax (planned)`, `CI-020 Resolution (planned)`, `CI-020 Errors (planned)` and point (2) of `CI-020 Pointer arguments for macros (planned)`, which allowed only the label and the mock value. A pointer can now read any column of the data dictionary row. (1) The optional last part of a pointer is one of `entity`, `field`, `dataType`, `label` or `mock` (`@User.FirstName.dataType`), always written exactly like that (case-sensitive); with no last part it is `mock`, as before. `entity`, `field`, `dataType` and `label` show the row's `entity`, `field`, `dataType` and `label`, and `mock` shows its `mockValue`. It works anywhere a pointer does, in a macro or written directly. (2) For an object parameter, a pointer argument `field=@User.FirstName` fills each declared field of the parameter that has the name of a column: `entity`, `field`, `dataType`, `label` and `mockValue` (which is read as `mock`), so `$field.dataType` becomes `@User.FirstName.dataType` and `$field.mockValue` becomes `@User.FirstName.mock`. A declared field that is not a column name gives `Field "<field>" of parameter "$<name>" is not a data dictionary column (expected entity, field, dataType, label or mockValue)`, which replaces the label-or-mockValue message. (3) The malformed-pointer message now reads `Invalid pointer "<token>" (expected @Entity.Field or @Entity.Field.<entity|field|dataType|label|mock>)`. The other errors, the entity-pointer error and the quote-dropping rule are unchanged.
* **[2026-11-23] CI-020 Not in this iteration (planned):** Left for later iterations, each needing its own decision: entity pointers (`@User`) and passing a record to a macro, a list of mock records per entity (`mocks`) and loops over it, the `@$param` marker in a `Def` signature (so for now any parameter accepts either a literal or a pointer, decided by the argument), comma-delimited list arguments, `$param` inside a pointer path (`@User.$field`), and pointers in a `Page` title. The seeded wire frames, the seeded global macros and the data dictionary table are not changed, and the data dictionary has no seed, so nothing in the app uses a pointer until the author writes one.
* **[2026-11-23] CI-020 Data references behaviour:** The `(planned)` product decisions of `CI-020` (`Two files, three stages`, `Pointer syntax`, `Literals and pointers`, `Resolution`, `Errors`, `Live preview`, `Pointer arguments for macros`, `Example`, `Any column` and `Not in this iteration`) are confirmed as implemented, with these clarifications and amendments. (1) A bare `@` argument for a plain parameter or the unlabeled `$1` is checked in the preprocessor with the same messages: `Invalid pointer "<token>" (expected ...)` for a malformed one and `Pointer "<token>" must name a field (expected @Entity.Field)` for an entity pointer, reported at the line of the use. (2) For an object parameter a pointer argument must have no column written: `field=@User.FirstName.label` is `Pointer "@User.FirstName.label" must name a field (expected @Entity.Field)`, because the columns are filled from the declared field names. (3) The preprocessor writes the `mockValue` field as `@User.FirstName.mock`, not `@User.FirstName` as sketched in the Syntax section; both resolve to the same text. (4) An object field can also be given a pointer in the dotted form (`field.label=@User.FirstName.label`), which is a normal bare named argument, and giving a field both from a pointer and dotted is `Duplicate argument "<name>.<field>"`. (5) A pointer followed by something that is not an attribute (`Box @User.FirstName extra`) is `Unexpected characters after pointer: " extra"`, like the existing message for text after a closing quote. (6) A pointer on a `Spacer` or an `Image` is reported as `Spacer cannot have text` or `Image cannot have text`, as a pointer is text. (7) A source compiled without a data dictionary (the argument is absent) behaves as one with no rows, so a pointer is an `Unknown entity` error. (8) A pointer followed by `.x` inside quotes in a macro body (`"$text.x"` for a plain parameter) is a literal, as the dot stays text. (9) The acceptance criterion `pnpm lint` could not be run: the repository has no `lint` script or linter configuration, so `pnpm typecheck` was run in its place.

* **[2026-11-23] CI-022 Table columns (planned):** A pointer can also be the header of a `TableColumn` (see `CI-022 TableColumn syntax (planned)` in `/capabilities/trellis-ast/capability.md`): `TableColumn @User.Name` shows the field's `label` as the column header and its `mockValue` as the cell value, so one pointer fills both. Only `@Entity.Field` is allowed there, with no suffix (a suffix such as `.label` is `Invalid pointer "<token>" (expected @Entity.Field)`), and the column cannot also have `|values`. It is resolved with the same lookup, first-row rule, errors (`Unknown entity`, `Unknown field`) and live preview as any other pointer. Everything else in this capability is unchanged.
* **[2026-11-23] CI-022 MockValues (follow-up):** This amends `CI-020 Resolution (planned)` and `CI-022 Table columns (planned)` now that the data dictionary column is `MockValues` (see the `data-dictionary` capability): a field's sample values are written in its cell separated by `;`, each trimmed (`Organisation Admin; Banan`), and an empty cell is one empty value. A pointer column of a `TableColumn` gets all of them as its `values`, so the table cycles them over its rows (`Organisation Admin`, `Banan`, `Organisation Admin`, ...) instead of repeating one string. Every other pointer that reads the mock values (`@Entity.Field` and `@Entity.Field.mock` on a node, and `.mock` passed through a macro) shows the first value only. `,` and `"` are not separators, so `"a","b"` stays one value. A macro that names the column `mockValue` in an object parameter (`$field=label|mockValue`) still works as `mockValues` (see the `macros` capability).

## Technical Decisions
* **[2026-11-23] CI-020 Schema (planned):** `src/web/schema/ast.ts` gets `PointerRefSchema = z.strictObject({ entity: z.string(), field: z.string(), kind: z.enum(["label", "mock"]), line: z.number().int().min(1) })` and `AstNodeSchema` gets `ref: PointerRefSchema.optional()` (omitted when the node has no pointer; `Page` has none, so a `ref` key on a page is rejected). A node with a `ref` has `text: ""` until it is resolved. `line` is the 1-based line of the text the core parser saw (the expanded text), so that the resolver can report it and `compileSyntax` can map it back. The structural `superRefine` rules for `Spacer` and `Image` also reject a `ref` there (they cannot have text). The resolved AST has no `ref` keys.
* **[2026-11-23] CI-020 Parser (planned):** `src/web/syntax/parse.ts` recognises, where the text of a node may start, an unquoted token that starts with `@` and reads it up to the next space as a pointer, using one `POINTER_PATTERN` (`/^@([A-Z][A-Za-z0-9]*)\.([A-Z][A-Za-z0-9]*)(?:\.(label|mock))?$/`) exported for the macro code. A token that starts with `@` and does not match is `Invalid pointer ...`, except that `@Entity` alone (matching `/^@[A-Z][A-Za-z0-9]*$/`) is the entity-pointer error. The `kind` is `mock` when no suffix is written. Quoted-text rules, attribute parsing and the other text errors are unchanged, and a `@` pointer on a `Page` line stays the existing bare-text error. `parseSyntax` does not read the data dictionary and keeps its signature.
* **[2026-11-23] CI-020 Resolver (planned):** A new pure, DOM-free module `src/web/syntax/resolve.ts` exports `resolveReferences(ast: Ast, rows: readonly DataDictionaryRow[]): ResolveResult`, with `ResolveResult = { ok: true; ast: Ast } | { ok: false; error: string }`. It walks every page's tree in source order, builds a lookup from `(entity, field)` to the first matching row once, and returns a new AST in which each node with a `ref` has `text` set to the row's `label` or `mockValue` and no `ref`. The first failing pointer gives `Line <line>: <message>`. An AST with no `ref` is returned as it is. It uses `DataDictionaryRow` from `src/web/data-dictionary/schema.ts` and passes the result through `AstSchema.safeParse`.
* **[2026-11-23] CI-020 Compile entry point (planned):** `compileSyntax(source, sharedMacros?, dataDictionary?)` in `src/web/syntax/compile.ts` gets a third argument, `readonly DataDictionaryRow[]` (absent means no rows). After `parseSyntax` succeeds it calls `resolveReferences` and rewrites the `Line <n>:` prefix of a resolver error with the same `origins` mapping (and ` (in macro "<Name>")`) as a core error. A source with no pointer returns exactly the result it did before.
* **[2026-11-23] CI-020 Macro changes (planned):** In `src/web/syntax/macros.ts` an argument value is marked as a pointer when it was written bare and starts with `@`; this is kept alongside the unquoted value in the argument map (for example a `pointer` flag per entry) so that substitution can tell a pointer from a literal. For an object parameter, `readNamedArgument` treats a bare, single, `@`-leading value as a pointer: it validates it against `POINTER_PATTERN` (without a suffix), and stores `name.label` as `@Entity.Field.label` and `name.mockValue` as `@Entity.Field.mock` for the fields declared, with the field error above for any other declared field. Substitution first matches a quoted string whose entire content is one placeholder (`"$name"` or `"$name.field"`, outside any other text) and, when the value is a pointer, replaces the quoted string with the bare pointer; every other placeholder is replaced as before. A value that itself contains `$name` is still not substituted again. `MacroDefinitionSchema` and `Def` parsing are unchanged, since pointer parameters need no declaration.
* **[2026-11-23] CI-020 Any column implementation (planned):** This amends `CI-020 Schema (planned)`, `CI-020 Parser (planned)`, `CI-020 Resolver (planned)` and `CI-020 Macro changes (planned)` for `CI-020 Any column (planned)`. `PointerRefSchema.kind` becomes `z.enum(["entity", "field", "dataType", "label", "mock"])` (exported as `POINTER_KINDS`, with the type derived through `z.infer`), and the `POINTER_PATTERN` suffix group becomes `(entity|field|dataType|label|mock)`. The resolver picks the value with a small lookup from `kind` to the `DataDictionaryRow` key (`mock` is `mockValue`, the others are the same name), so a new column needs one entry. In `macros.ts` the pointer-argument expansion uses a lookup from a declared field name to its pointer suffix (`mockValue` to `mock`, the other four names to themselves) built from the same `POINTER_KINDS`, and a declared name not in it is the new error.
* **[2026-11-23] CI-020 Components (planned):** `WireframeEditor` (`src/web/viewer/wireframe-editor.tsx`) and `MacroEditor` (`src/web/macros/macro-editor.tsx`) get an optional `dataDictionary?: readonly DataDictionaryRow[]` prop and pass it to `compileSyntax`; the parse is memoised on it. `FeatureDetailsLoader` already loads the rows and passes them through `FeatureDetailsView`, which now also gives them to the editor and waits for them (as it already waits for the macros) before showing the editor. `MacrosPage` loads the rows with `getDataDictionary()` in its own effect and waits for them before showing `MacroEditor`. No new component is added.
* **[2026-11-23] CI-020 Data references implementation:** The `(planned)` technical decisions of `CI-020` (`Schema`, `Parser`, `Resolver`, `Compile entry point`, `Macro changes`, `Any column implementation` and `Components`) are confirmed as implemented, with these amendments. (1) The pointer shape lives in a new DOM-free module `src/web/syntax/pointer.ts`, not in `parse.ts`: it exports `POINTER_PATTERN` (built from `POINTER_KINDS`, so a new column needs one entry), `POINTER_COLUMNS` (the lookup from a kind to the `DataDictionaryRow` key, used by the resolver and, reversed, by the macro code), `parsePointer(token)` (the parts of a valid pointer, or the error message without a line, for both the invalid and the entity case) and `mustNameFieldError(token)`. `parse.ts` and `macros.ts` both use it, so the messages are written once. The entity-pointer pattern is private to it. (2) `src/web/schema/ast.ts` exports `POINTER_KINDS`, `PointerKind`, `PointerRefSchema` and `PointerRef` as decided; the `Spacer` and `Image` rules of `AstSchema` report a `ref` with their `cannot have text` message. (3) In `parse.ts` the pointer is read in `parseRest` before the quoted-text and attribute branches, except for `Page`, which keeps the existing bare-text error; the node gets `ref` (with the `line`) and `text: ""`. (4) `resolveReferences` resolves a node's own pointer before its children so that the first error in source order is the one reported; the lookup is a nested `Map` built once per call, and an AST without a `ref` is returned as the same object. (5) `compileSyntax`'s third argument defaults to no rows. (6) In `macros.ts` arguments are stored in the existing `Map` as `{ value, pointer }`; `readNamedArgument` returns each value with whether it was written bare, and `parseArguments` marks a bare `@`-leading value as a pointer after validating it with `parsePointer`. A single bare `@` value for an object parameter is expanded into `name.field` entries from the `COLUMN_KINDS` lookup. Substitution runs two passes over each body line: `QUOTED_PARAM_REFERENCE` (the `PARAM_REFERENCE` pattern between quotes) replaces a quoted placeholder by the bare pointer when its argument is a pointer and leaves it otherwise, then `PARAM_REFERENCE` substitutes every other placeholder as before, so a substituted value is never scanned again. (7) `WireframeEditor`, `MacroEditor` and `MacrosView` take the optional `dataDictionary` prop (`MacrosView` passes it to `MacroEditor`), `FeatureDetailsView` passes the rows it already has to `WireframeEditor`, and `FeatureDetailsLoader` and `MacrosPage` return nothing until the data dictionary has loaded. (8) Tests: `ast.test.ts`, `parse.test.ts`, `resolve.test.ts` (new), `compile.test.ts`, `macros.test.ts`, `wireframe-editor.test.tsx`, `macro-editor.test.tsx` and `features.test.tsx`; typing and the loaders are not DOM-tested.

## Syntax

```
Def Field $field=label|mockValue
  Text "$field.label"
  Box "$field.mockValue"

Page "Profile"
  Field field=@User.FirstName
  Text @User.LastName.label font=bold
  Box @User.LastName
```

With the data dictionary row `User`, `FirstName`, label `First Name`, mock value `Jane` and the row `User`, `LastName`, label `Last Name`, mock value `Smith`, the macro preprocessor produces:

```
Page "Profile"
  Text @User.FirstName.label
  Box @User.FirstName
  Text @User.LastName.label font=bold
  Box @User.LastName
```

and the resolver then gives the same AST as `Text "First Name"`, `Box "Jane"`, `Text "Last Name" font=bold` and `Box "Smith"`.

Grammar (informal): in the core syntax `line = indent Type [" " (quoted | pointer)] (" " attribute)*` (a pointer only where text is allowed, so not on `Page`, `Spacer` or `Image`), `pointer = "@" Name "." Name ["." ("entity" | "field" | "dataType" | "label" | "mock")]`, `Name = [A-Z][A-Za-z0-9]*`. In a macro use, an argument value that is written bare and starts with `@` is a pointer: `argument = ident "=" ("@" Name "." Name | ...)`.

## Data Dictionary
- `Pointer`: A reference from a wire frame to a column of a data dictionary row, written `@Entity.Field` or `@Entity.Field.<entity|field|dataType|label|mock>`. It exists only in source text and, before resolution, in the AST; it is never stored.
- `Pointer.entity`: The `Entity` name of the data dictionary row it points at (Pascal case, case-sensitive).
- `Pointer.field`: The `Field` name of the data dictionary row it points at (Pascal case, case-sensitive).
- `Pointer.kind`: Which column is shown: `entity`, `field`, `dataType`, `label` (the row's column of that name) or `mock` (the row's `mockValue`; the default when no suffix is written).
- `ref`: Optional on a node in the AST before resolution: the `entity`, `field`, `kind` and source `line` of the node's pointer, with `text: ""`. Omitted when the node's text is a literal, and always absent after resolution.
