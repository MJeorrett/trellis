# Capability: Wire Frame Viewer

## User Need
As a user, I want to be able to view a wire frame of a UI component tree so that I can see the structure of the UI.

## Product Decisions
* **[2026-11-20] CI-003 Input:** The viewer's input is now the custom indentation-based syntax defined in `/capabilities/trellis-ast/capability.md`, not JSON. `App.tsx` parses the text area with `parseSyntax` (`src/syntax/parse.ts`) and shows parse errors inline, with their line number, under the text area. The JSON input and `parseAstJson` were removed; the default sample (`src/viewer/sample.ts`, `sampleSource`) is the Login Form in the new syntax.
* **[2026-11-20] CI-005 Pages (planned):** The wire frame source can now describe several pages (see the `Page` decisions in `/capabilities/trellis-ast/capability.md`). The preview shows one tab per page, in source order, labelled with the page's title, and only the selected page's content is rendered. Tabs are always shown, even for a single page. A page with an empty title is labelled `Page N` (its 1-based position). The first page is selected initially. When the source is edited, the selected tab is kept by position and falls back to the last page if that position no longer exists; if the source has a syntax error, the previous preview behaviour applies (the error is shown under the text area).
* **[2026-11-20] CI-005 Pages implementation:** The `CI-005 Pages (planned)` decision is confirmed as implemented. Clarifications: the page's content is its children stacked in a column (the `Page` itself has no border or title text); selection is kept by position and resolved when rendering, so the stored position is not overwritten when it falls back (if the source later regains pages, the earlier tab is selected again), and a syntax error leaves the selection untouched. The blank source shows one tab labelled `Page 1` with no content. The default sample shows a `Log in` tab and a `Forgot password` tab.
* **[2026-11-20] CI-006 Links (planned):** A `Box` or `Text` with a `link-to` (see `/capabilities/trellis-ast/capability.md`) is a link in the preview. It shows a pointer cursor (`cursor-pointer`) over the whole node, including its children that are not links themselves. Clicking it opens the target: the page whose `id` equals the link target becomes the selected tab and its content is shown, exactly as if the tab had been clicked. If the node is nested inside another link, only the innermost link reacts. Nodes without `link-to` are unchanged (no pointer cursor, no click behaviour).
* **[2026-11-20] CI-006 Unknown target (planned):** Clicking a link whose target id matches no page does not change the selected tab and shows a toast notification saying the page was not found, naming the id (e.g. `Page "test-id" not found`). Such a link still shows the pointer cursor, since the source may be mid-edit; the toast is the feedback. Selecting a page by link follows the existing selection rules (stored by position), so editing the source afterwards behaves as before.
* **[2026-11-20] CI-006 Links implementation:** The `CI-006 Links (planned)` and `CI-006 Unknown target (planned)` decisions are confirmed as implemented, with these clarifications. (1) Linked nodes keep their normal look (a linked `Text` stays borderless); the only visual change is the pointer cursor. (2) The toast is an error toast with the message `Page "<id>" not found`. (3) Keyboard access is Enter on a focused linked node only (it does not react to Enter pressed inside a nested focusable child). (4) The default sample links the two pages to each other: `Log in` (`id=login`) has `Text "Forgot password?" link-to=forgot` and `Forgot password` (`id=forgot`) has `Text "Back to log in" link-to=login`.
* **[2026-11-21] CI-007 Route (planned):** The wire frame demo (source editor and preview, unchanged in behaviour) moves to its own route, `/wireframe-demo`. It is no longer shown at `/`, which redirects to the features page (see the `features` capability for the route table).
* **[2026-11-21] CI-007 Route implementation:** The `CI-007 Route (planned)` decision is confirmed as implemented: the wire frame demo works at `/wireframe-demo` with unchanged behaviour (source editor, `PageTabs` preview, sample, links and toasts), and `/` redirects to `/features`. The README demo link and screenshot refer to `/wireframe-demo`.
* **[2026-11-21] CI-008 Route (planned):** This supersedes `CI-007 Route (planned)`. The wire frame demo page and its `/wireframe-demo` route are removed (the path now redirects to `/features`). The source editor and preview, with unchanged behaviour (parse errors, `PageTabs`, links and toasts), are shown on the details page of a feature, `/features/:id`, and edit that feature's own wire frame source instead of one shared sample. See the `features` capability. The default sample is no longer shown on its own: it becomes the wire frame source of the first seeded feature.
* **[2026-11-21] CI-008 Route implementation:** The `CI-008 Route (planned)` decision is confirmed as implemented: the viewer only exists on `/features/:id`, `/wireframe-demo` redirects to `/features`, and the editor behaviour (inline parse errors, `PageTabs` preview, links and the not-found toast) is unchanged. The README demo link points to `/features` and the screenshot is kept as an illustration of the editor on a details page.
* **[2026-11-22] CI-009 Sketchy look (planned):** The wire frame preview looks hand-drawn, like a sketch on paper, instead of crisp boxes. Every `Box`, `Row` and `Text` in the preview is drawn with a handwriting font, and bordered nodes (`Box`, `Row`) get uneven, wobbly corners and a slightly irregular border. Each node is tilted by a tiny amount (well under 1 degree) so a column of boxes does not look machine-aligned. The look is deterministic: the same source always renders the same sketch, and typing in the editor does not make unrelated nodes jump around. It is always on (no toggle). Only the wire frame nodes are affected; the page tabs, the preview card, the editor and the rest of the app keep their current look. Behaviour does not change: layout (`Box` and `Text` in a column, `Row` on one non-wrapping row), links (pointer cursor, click, Enter), the text and the page contents are exactly as before, and the tilt must not make text unreadable or break clicking a link.
* **[2026-11-22] CI-009 Sketchy look implementation:** The `CI-009 Sketchy look (planned)` decision is confirmed as implemented, unchanged. The tilt is at most 0.8 degrees either way, and the look is limited to the wire frame nodes; the README notes the look and that the existing screenshot predates it.

* **[2026-11-22] CI-009 Less sketchy:** This amends `CI-009 Sketchy look implementation`: the look was too wobbly, so it is now 0.4 times as sketchy. Both the corner wobble and the tilt are scaled by 0.4, so tilts are now at most 0.32 degrees either way (previously 0.8). Everything else about the look is unchanged.
* **[2026-11-22] CI-009 Sketchiness in the middle:** This supersedes the factor in `CI-009 Less sketchy`: 0.4 was a bit too tame, so the look is now 0.7 times the original, between the original and the 0.4 version. Tilts are at most 0.56 degrees either way. Everything else is unchanged.
* **[2026-11-22] CI-009 Segoe Print:** This supersedes the `Caveat` font in the `CI-009` sketchy look decisions: the wire frame nodes now use the `Segoe Print` handwriting font. It is a Windows system font, so on systems without it the preview falls back to the browser's default `cursive` font, and then to sans-serif.
* **[2026-11-22] CI-010 Spacer (planned):** A `Spacer` (see `/capabilities/trellis-ast/capability.md`) shows in the preview as empty space, not as a visible element: it has no border, text, tilt or pointer cursor, and it stretches to fill the remaining width of its `Row`, so elements before it stay at the left and elements after it are pushed to the right. Everything else about the preview is unchanged.
* **[2026-11-22] CI-011 Width (planned):** In the preview, the children of a `Row` that has at least one child with a `width` (see `/capabilities/trellis-ast/capability.md`) are laid out in twelfths of the row: a child with `width=N` takes N/12 of the row's width, and a child without one takes 3/12. A `width=3` and a `width=9` child take a quarter and three quarters of the row. Widths are literal, so a row adding up to less than 12 leaves empty space on its right and one adding up to more than 12 overflows without wrapping. A `Spacer` in such a row is a gap of its own width (3/12 by default) instead of filling the remaining space. A `Row` with no `width` among its children, and anything outside a `Row`, looks exactly as before.
* **[2026-11-22] CI-012 BoxRow (planned):** In the preview a `BoxRow` looks and behaves exactly as a `Row` does today: a bordered node with wobbly corners, its children on one non-wrapping row, `width` layout in twelfths (see `CI-011 Width (planned)`) and a `Spacer` that fills the remaining space of its direct parent. A `Row` is now borderless and has no wobbly corners (like `Text`), but keeps the handwriting font, the tiny tilt, the padding, the gap, the single non-wrapping row and the same `width` and `Spacer` behaviour, so swapping `Row` for `BoxRow` only adds the border. A borderless `Row` shows nothing but its children. This amends the bordered `Row` in the CI-004 and CI-009 decisions. Everything else is unchanged.
* **[2026-11-22] CI-013 Font and font size (planned):** In the preview a node with `font=bold` (see `/capabilities/trellis-ast/capability.md`) shows its own text in bold, and `font-size` sets the size of its own text: `sm` smaller than today, `md` (the default) exactly as today and `lg` larger. Neither is inherited: children of a node keep their own font and size. The handwriting font, tilt, border, layout, links and everything else are unchanged, and a node without the attributes looks exactly as before.
* **[2026-11-22] CI-013 Font and font size implementation:** The `CI-013 Font and font size (planned)` decision is confirmed as implemented, unchanged: `font=bold` renders the node's own text in bold and `font-size` renders `sm` smaller (`text-xs`), `md` or absent as before (`text-sm`) and `lg` larger (`text-base`), with no inheritance by children. The rendering matches the plan. The technical details are in `/capabilities/trellis-ast/capability.md` (`CI-013 Font implementation`).

## Technical Decisions
* **[2026-11-20] CI-002 Tooling:** Implemented in a minimal Minimal React App using Vite, shadcn and Tailwind CSS.
* **[2026-11-20] CI-002 Setup:** Vite 8 + React 19 + Tailwind CSS v4 (`@tailwindcss/vite`) + shadcn (initialised with `--defaults`; `button`, `card`, `textarea` added). Alias `@` -> `src`. Run with `pnpm dev`; build with `pnpm build`. The app lives alongside the schema in `src/` (`main.tsx`, `App.tsx`, `viewer/`).
* **[2026-11-20] CI-002 Rendering:** `WireframeNode` (`src/viewer/wireframe.tsx`) recursively renders nodes as column-flex `div`s. `Box` has a border; `Text` is identical without one, derived from `type` per the `trellis-ast` decision. Empty `text` renders nothing. Nodes expose a `data-node-type` attribute (`data-node-id` was removed in CI-003 as nodes no longer have ids); children are keyed by index.
* **[2026-11-20] CI-004 Row rendering:** `WireframeNode` renders `Row` as a bordered container with `flex-row flex-nowrap`, so its children sit on one row and never wrap; `Box` stays column-flex with a border and `Text` column-flex without one. `data-node-type="Row"` is exposed like the other types. The default sample now ends with a `Row` holding Cancel and Submit buttons.
* **[2026-11-20] CI-006 Link rendering (planned):** `WireframeNode` (`src/viewer/wireframe.tsx`) takes an `onLink?: (target: string) => void` prop (passed down recursively). When `node.linkTo` is set it adds `cursor-pointer`, a `data-link-to` attribute and a click handler that calls `event.stopPropagation()` and then `onLink(node.linkTo)`, so only the innermost link fires. It is a click handler on the existing `div`, with `role="link"` and `tabIndex={0}` plus Enter-key activation for keyboard access. `PageTabs` receives the page list and gets an `onLink` that is wired to a pure function `findPageIndexById(pages, id): number | undefined` (in `src/viewer/pages.tsx`) which returns the page position, or `undefined` for an unknown id. A known id calls `onSelect(index)`; an unknown id shows a toast. Toasts use the shadcn `sonner` component (`pnpm dlx shadcn@latest add sonner`), with `<Toaster />` mounted once in `App.tsx`. The generated component must not depend on `next-themes` (the app has no theme provider), so it is adjusted if necessary.
* **[2026-11-20] CI-006 Link implementation:** Implemented as planned. `WireframeNode` takes `onLink` and, for a node with `linkTo`, adds `cursor-pointer`, `role="link"`, `tabIndex={0}`, `data-link-to`, a click handler (with `stopPropagation`) and an Enter handler. `src/viewer/pages.tsx` exports `findPageIndexById(pages, id)`, `resolveLink(pages, id)` (`{ index }` or `{ notFound }`) and `linkNotFoundMessage(id)`; `PageTabs` uses them in its `onLink` (select the page, or `toast.error` from `sonner`). `src/components/ui/sonner.tsx` was added with `pnpm dlx shadcn@latest add sonner`; the generated component used `next-themes`, so it was edited to `theme="system"` and the `next-themes` dependency that the command added was removed with `pnpm remove next-themes`. `<Toaster />` is mounted once in `App.tsx`. Tests: `wireframe.test.tsx` (link markup and classes) and `pages.test.tsx` (`findPageIndexById`, `resolveLink`, message, links rendered in `PageTabs`); the click handler and toast themselves are not DOM-tested (no DOM test setup), only the pure logic behind them.
* **[2026-11-21] CI-007 Demo component:** The previous `App` content moved unchanged into `WireframeDemo` (`src/pages/wireframe-demo.tsx`), except that `<Toaster />` is no longer inside it: it is mounted once in `App.tsx` outside the routes, so the link-not-found toast still works. The `CI-006 Link implementation` note that `<Toaster />` is mounted in `App.tsx` therefore still holds.
* **[2026-11-21] CI-008 Editor component (planned):** The source editor and preview are extracted from the removed `WireframeDemo` into `WireframeEditor` (`src/viewer/wireframe-editor.tsx`), with props `source` and `onSourceChange`, which owns the parse result and the selected page tab. `src/viewer/sample.ts` is removed; its Login Form source moves to `src/features/wireframes/` (see the `features` capability).
* **[2026-11-21] CI-008 Editor implementation:** The `CI-008 Editor component (planned)` decision is confirmed as implemented. `WireframeEditor` (`src/viewer/wireframe-editor.tsx`, props `source` and `onSourceChange`) is a controlled component: it renders the two cards (source `Textarea` with inline parse error, and `PageTabs` preview) in a two-column grid and owns only the parse result (memoised from `source`) and the selected page position. The page wrapper (`main`) now belongs to the feature details page, not the editor. `src/viewer/sample.ts` and `src/pages/wireframe-demo.tsx` are deleted.
* **[2026-11-22] CI-009 Sketchy rendering (planned):** Pure CSS, no drawing library. The handwriting font is `Caveat`, added with `pnpm add @fontsource-variable/caveat` and imported in `src/main.tsx`; it is applied only inside `WireframeNode` (not app-wide). The wobbly corners are an irregular `border-radius` (the eight-value `a b c d / e f g h` form) and the tilt is a small `rotate` transform. Both come from a small, pure, DOM-free function in `src/viewer/sketch.ts`, `sketchStyle(seed: number): { borderRadius: string; transform: string }`, which picks from a fixed set of variants (no `Math.random`, so renders are stable). The seed is derived from the node's position (its child index path from the page root) so it does not change when the text changes; `WireframeNode` receives that path through an optional prop (default empty) that it extends for its children. `Text` nodes get the font and tilt but no border radius (they have no border). The style is applied inline on the existing `div`, so layout classes, `data-node-type`, link attributes and handlers are unchanged. Rotation uses `transform`, so it does not affect layout.
* **[2026-11-22] CI-009 Sketchy rendering implementation:** The `CI-009 Sketchy rendering (planned)` decision is confirmed as implemented, with these details. (1) `src/viewer/sketch.ts` exports `sketchStyle(seed)`, which indexes a fixed list of 6 variants by `Math.abs(Math.trunc(seed)) % 6` (rotations between -0.8 and 0.7 degrees), and `seedFromPath(path)`, an FNV-1a hash of the path (prefixed by its length, so `[0]` and `[0, 0]` differ) that yields a non-negative integer. (2) `WireframeNode` takes `path?: readonly number[]` (default `[]`) and passes `[...path, index]` to children; the node's own index is part of its path, so `PageTabs` passes `path={[index]}` for each top-level child. The page index is not part of the path, so the same position on different pages looks the same. (3) The font is applied with inline `fontFamily` (`'Caveat Variable', cursive, sans-serif`) on each wire frame node, together with `transform` and, except for `Text`, `borderRadius`; `@fontsource-variable/caveat` is imported in `src/main.tsx`. (4) Tests: `src/viewer/sketch.test.ts` and a `WireframeNode sketch style` block in `wireframe.test.tsx` (`renderToStaticMarkup`, no DOM).
* **[2026-11-22] CI-009 Sketchiness constant:** This amends `CI-009 Sketchy rendering implementation` point (1). `src/viewer/sketch.ts` now has a `SKETCHINESS` constant (`0.4`; `1` is the original look) that scales the base variants' corner radii and tilts when `VARIANTS` is built. The base radii were also lowered from 15 to 255px to 6 to 60px, because browsers clamp oversized radii on short boxes (the original values were clamped, so scaling them alone would barely have changed small boxes). The variant count, the `sketchStyle` and `seedFromPath` signatures and the eight-value format are unchanged.
* **[2026-11-22] CI-009 Sketchiness value:** This supersedes the value in `CI-009 Sketchiness constant`: `SKETCHINESS` in `src/viewer/sketch.ts` is now `0.7` (was `0.4`). Nothing else about it changes.
* **[2026-11-22] CI-009 Segoe Print font:** This supersedes the font parts of `CI-009 Sketchy rendering (planned)` and `CI-009 Sketchy rendering implementation`. `SKETCH_FONT` in `src/viewer/wireframe.tsx` is now `'Segoe Print', cursive, sans-serif`, still applied inline on each wire frame node only. Nothing is bundled: the `@fontsource-variable/caveat` dependency was removed with `pnpm remove` and its import was deleted from `src/main.tsx`. The test now checks for `Segoe Print`.

* **[2026-11-22] CI-010 Spacer implementation:** The `CI-010 Spacer (planned)` decision is confirmed as implemented, unchanged: the rendering matches the plan. `WireframeNode` returns early for a `Spacer` with `<div data-node-type="Spacer" className="flex-1" />`, so it has no border, font, tilt, radius, link attributes, text or children, and the sketch seeds of its siblings are unchanged (paths still use child indexes, including the `Spacer`'s own). Tests (`renderToStaticMarkup`) in `wireframe.test.tsx` check the order, the `flex-1` class and the absence of border and inline styles.
* **[2026-11-22] CI-011 Width implementation:** The `CI-011 Width (planned)` decision is confirmed as implemented, unchanged: the rendering matches the plan. `rowWidths` (`src/viewer/layout.ts`) resolves the widths and `WireframeNode` gives each child of a `Row` with widths an inline `flex: 0 0 calc((100% - <gaps>) * N / 12)` and `min-width: 0` (gaps are `(children - 1) * 0.5rem`), so widths adding up to 12 fill the row exactly. A `Spacer` with a resolved width is an empty fixed-width `div` without `flex-1`; a `Spacer` in a row without widths keeps `flex-1`. Rows without widths, and a `width` outside a `Row`, render exactly as before. Tests in `layout.test.ts` and `wireframe.test.tsx`.
* **[2026-11-22] CI-012 BoxRow rendering (planned):** In `WireframeNode` (`src/viewer/wireframe.tsx`) "is a row" (`flex-row flex-nowrap`, and the call to `rowWidths` for the children) is true for both `Row` and `BoxRow`, and "has a border" (`border border-foreground/60` and the `borderRadius` from `sketchStyle`) is true for every type except `Text` and `Row`. `data-node-type` is the node's own type (`Row` or `BoxRow`). The sketch seeds (paths), link handling and slots are unchanged.
* **[2026-11-22] CI-012 BoxRow implementation:** The `CI-012 BoxRow (planned)` product decision and the `CI-012 BoxRow rendering (planned)` technical decision are confirmed as implemented; the rendering matches the plan. In `WireframeNode` (`src/viewer/wireframe.tsx`) two local values, `isRow` (`Row` or `BoxRow`) and `hasBorder` (every type except `Text` and `Row`), drive the `flex-row flex-nowrap` class, the `rowWidths` call, the `border border-foreground/60` classes and the inline `borderRadius`. A `Row` therefore has the font, tilt, padding and gap but no border classes and no `border-radius`. Tests in `wireframe.test.tsx` (`renderToStaticMarkup`) cover `Row`, `BoxRow`, `width` and `Spacer` in a `BoxRow`; `layout.ts` and `layout.test.ts` are unchanged.
