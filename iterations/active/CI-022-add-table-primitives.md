# Iteration CI-022: Add Table Primitives

**Target Capability:** `/capabilities/trellis-ast/capability.md`

## User Story
As a Trellis user or AI agent, I want built-in `Table` and `TableColumn` elements, so that I can sketch a data table in a wire frame in a few lines (`Table` with the children `TableColumn @User.Name width=4`, `TableColumn @User.Email width=5`, `TableColumn "Manual Column"|"mock 1","mock 2","mock 3"` and `TableColumn "Edit"|"Edit user" width=2 link-to=edit-user`) instead of building a grid of boxes by hand.

Read the `CI-022` entries in the Product and Technical Decisions of the target capability, the `CI-022 Table (planned)` entry in `/capabilities/wire-frame-viewer/capability.md`, the `CI-022 Table columns (planned)` entry in `/capabilities/data-references/capability.md` and the `CI-022 Table is a core type (planned)` entry in `/capabilities/macros/capability.md` before starting. They define the structure, the column syntax and its exact errors, the 10 rows and cycling of values, the widths, the pointer columns and the rendering.

## Acceptance Criteria
1. `NodeTypeSchema` in `src/web/schema/ast.ts` is `z.enum(["Box", "Text", "Row", "BoxRow", "Spacer", "Image", "Table", "TableColumn"])` and `AstNodeSchema` has an optional `values` (`z.array(z.string())`), omitted when not written. `AstSchema` rejects (via `superRefine`) a `Table` with non-empty `text`, a `ref`, `values`, `linkTo`, `width`, `font`, `fontSize` or `aspectRatio`, with no children, or with a child that is not a `TableColumn`; and a `TableColumn` that is not a direct child of a `Table`, has children, or has a `font`, `fontSize` or `aspectRatio`; `values` on any other type, and `values` together with a `ref`, are rejected too. `linkTo` and `width` are accepted on a `TableColumn`. `src/web/schema/ast.test.ts` covers valid tables (in a page, `Box`, `Row` and `BoxRow`, with literal and pointer columns) and each rejection.
2. `parseSyntax` in `src/web/syntax/parse.ts` accepts `Table` and `TableColumn` (case-sensitive; `table` is still an unknown type with its line number). It produces, for a literal column, `{ type: "TableColumn", text: "<header>", children: [], values: [...] }` (no `values` key when there is no `|values`), and for a pointer column `{ type: "TableColumn", text: "", children: [], ref: { entity, field, kind: "mock", line } }`, plus `width` and `linkTo` when written (in either order). `Table` produces `{ type: "Table", text: "", children: [...] }`. Quoted headers and values may contain spaces, `|` and `,`, and `""` is valid for both.
3. `parseSyntax` reports these fail-fast errors with the 1-based line number, each with its exact message from `CI-022 Table errors (planned)`: `TableColumn must be inside a Table`; `Table can only contain TableColumn` (on the child's line); `Table must have at least one TableColumn` (on the `Table`'s line, including when the table is followed by a sibling line or ends the source); `Table cannot have text` (`Table ""` is accepted); `Table cannot have <key>` (e.g. `width`); `TableColumn cannot have children` (on the child's line); `TableColumn cannot have font`, `font-size`, `id` and `aspect-ratio`; `TableColumn requires a header`; `Invalid table column values (expected "Header"|"value","value")` for a bad value list (missing value, trailing or doubled comma, bare value, space around `|` or `,`, unterminated string); `A pointer column cannot have values`; `Invalid pointer "<token>" (expected @Entity.Field)` for a malformed pointer or one with a suffix; and `Pointer "<token>" must name a field (expected @Entity.Field)` for an entity pointer. The unknown-type message is `Unknown type "<name>" (expected Box or Text or Row or BoxRow or Spacer or Image or Table or TableColumn)`, and existing tests that assert it are updated.
4. `src/web/syntax/parse.test.ts` covers: the full example table of the user story, a `Table` as a child of a `Page`, `Box`, `Row` and `BoxRow`, a literal column with no values, one value and several values, a pointer column, `width` and `link-to` in both orders, and every error above with its exact message.
5. `resolveReferences` in `src/web/syntax/resolve.ts` resolves a pointer `TableColumn` to `text` = the row's `label` and `values` = `[row.mockValue]` with no `ref`, using the existing lookup, first-row rule and the `Unknown entity` / `Unknown field` errors. `compileSyntax` maps those errors to the line of the source (and the macro) as for other pointers. `src/web/syntax/resolve.test.ts` and `compile.test.ts` cover a resolved column, a column whose field has an empty label or mock value, both errors, and a table inside a macro body that uses `$param` in a header and a value list.
6. `Table` and `TableColumn` are reserved macro names, derived from `NodeTypeSchema.options`: `Def Table` and `Def TableColumn` give `Macro name "<name>" is reserved`, and a use line starting with either is not treated as a macro use. `src/web/syntax/macros.test.ts` covers both.
7. `src/web/viewer/table.ts` exports `TABLE_ROWS` (`10`), `tableCells(values, rows = TABLE_ROWS)` (the values cycled to `rows` cells and cut to `rows`; `rows` empty strings when there are none) and `tableColumnWidths(columns)` (each column's `width` or `3` when at least one column has a `width`, otherwise `undefined`). `src/web/viewer/table.test.ts` covers: 1, 3, 10 and 12 values, no values, and widths with none, some and all written.
8. `WireframeNode` in `src/web/viewer/wireframe.tsx` renders a `Table` as one bordered container with `data-node-type="Table"`, the handwriting font, `borderRadius` and tilt from `sketchStyle` of its path, holding a CSS grid with one track per `TableColumn` (`repeat(n, minmax(0, 1fr))` when `tableColumnWidths` is `undefined`, otherwise one `calc(100% * <width> / 12)` track per column), no gap between cells, a header row of bold cells showing each column's `text`, and `TABLE_ROWS` data rows of bordered cells showing `tableCells(column.values ?? [])`. Cells have no tilt of their own. The data cells of a column with `linkTo` have the link attributes and handlers of a linked `Box` (`role="link"`, `tabIndex`, `data-link-to`, `cursor-pointer`, click and Enter calling `onLink`); header cells never do. Other types render as before.
9. `src/web/viewer/wireframe.test.tsx` verifies with `renderToStaticMarkup`: a `Table`'s container classes and `data-node-type="Table"`, one bold header cell per column, exactly 10 data rows per column with the cycled values, the equal and the `width` grid templates (including the default 3 and a total over 12), that linked columns have link attributes on the data cells only, and that a `Table` in a `Row` with `width` gets the slot style.
10. `WireframeEditor` shows the preview of a source with a table, including the example of the user story with a data dictionary that has `User.Name` and `User.Email`, and `Fix the source to see the wire frame.` for a table error. `src/web/viewer/wireframe-editor.test.tsx` covers both.
11. `pnpm test` and `pnpm build` pass.
12. Updates `README.md` (syntax section: `Table` and `TableColumn`, with the example and the pointer, `|values`, `width` and `link-to` rules) and the Syntax and Data Dictionary sections of the target capability (`Type` list, grammar for `Table` and `TableColumn`, the `values` entry and the `type` entry), and logs the implementation decisions in the target capability's Product Decisions or Technical Decisions (and notes in `/capabilities/wire-frame-viewer/capability.md`, `/capabilities/data-references/capability.md` and `/capabilities/macros/capability.md` if the behaviour differs from the plan).
