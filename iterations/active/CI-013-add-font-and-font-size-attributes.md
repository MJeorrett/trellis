# Iteration CI-013: Add Font and Font Size Attributes

**Target Capability:** `/capabilities/trellis-ast/capability.md`

## User Story
As a Trellis user or AI agent, I want `font=bold` and `font-size=sm|md|lg` attributes on `Box`, `Text`, `Row` and `BoxRow` so that I can make headings and emphasis stand out in a wire frame (`md` is the default size).

Read the `CI-013` entries in the Product and Technical Decisions of the target capability, and the `CI-013 Font and font size (planned)` entry in `/capabilities/wire-frame-viewer/capability.md`, before starting. They define the allowed values, which types accept the attributes, that they apply to the node's own text only (no inheritance), the exact syntax errors and the representation.

## Acceptance Criteria
1. `src/schema/ast.ts` exports `FontSchema = z.literal("bold")` and `FontSizeSchema = z.enum(["sm", "md", "lg"])`, and `AstNodeSchema` has optional `font` and `fontSize` keys (omitted when absent, still a `z.strictObject`). `src/schema/ast.test.ts` covers: `font: "bold"` and each `fontSize` on `Box`, `Text`, `Row` and `BoxRow`; rejection of other values (`"italic"`, `"xl"`, a non-string); rejection of `font` and `fontSize` on a `Spacer`; and rejection of a `font` or `fontSize` key on a `Page`.
2. `parseSyntax` in `src/syntax/parse.ts` accepts `font=bold` and `font-size=sm|md|lg` on `Box`, `Text`, `Row` and `BoxRow` (after the optional quoted text, alone or combined with each other, `link-to` and `width` in any order) and produces `font` and `fontSize` on the node only when written (`font-size=md` is kept as written). Ids, links and widths are unchanged.
3. `parseSyntax` reports these fail-fast errors with the 1-based line number: `Line <n>: Page cannot have font`, `Page cannot have font-size`, `Spacer cannot have font` and `Spacer cannot have font-size`; `Line <n>: Attribute "font" requires the value bold` for `font=`, `font=italic` and `font=Bold`; `Line <n>: Attribute "font-size" requires one of sm, md or lg` for `font-size=`, `font-size=xl` and `font-size=LG`; and `Line <n>: Duplicate attribute "font"` and `Duplicate attribute "font-size"`. The unsupported-kind check runs before the value check (`Page "x" font=italic` reports `Page cannot have font`), and `Spacer width=2` is still accepted.
4. `src/syntax/parse.test.ts` covers: `font` and `font-size` on each of `Box`, `Text`, `Row` and `BoxRow` (full AST), each size value, all four attributes together in more than one order, the attributes with text omitted (`Text font=bold`), and every error above with its exact message.
5. `WireframeNode` in `src/viewer/wireframe.tsx` applies a size class from `node.fontSize` (`sm` is `text-xs`, `md` or absent is `text-sm`, `lg` is `text-base`, through a small pure lookup) and `font-bold` when `node.font === "bold"`, and children do not inherit the parent's weight or size (each node sets its own size class and resets the weight with `font-normal` unless bold). A node without the attributes renders with the same markup as before, apart from `font-normal` where that is needed. `src/viewer/wireframe.test.tsx` (with `renderToStaticMarkup`) verifies each size class, bold, a bold parent with a non-bold child (child has `font-normal`, no `font-bold`), a `lg` parent with a child without `font-size` (child has `text-sm`), and that a `Spacer` is unchanged.
6. The three seeded samples in `src/features/wireframes/` (`wire-frame-editor.ts`, `page-links.ts`, `features-list.ts`) are updated as described in `CI-013 Samples (planned)`, so each uses `font=bold` and `font-size` (`sm` and `lg`) somewhere, and still parse without error. `src/syntax/parse.test.ts` sample tests (and any other test that asserts the sample sources) are updated to expect the new attributes in the parsed ASTs, and a test checks that every seeded sample source parses and contains at least one `font` and one `fontSize`.
7. `pnpm test` passes and `pnpm build` succeeds.
8. Updates `README.md` (the syntax section: `font` and `font-size` attributes, their values, the default size, which types accept them and that they are not inherited; and its Login Form example) and the Syntax (grammar and example) and Data Dictionary (`font`, `fontSize`) sections of the target capability, and logs the implementation decisions in the target capability's Product Decisions or Technical Decisions (and a note in `/capabilities/wire-frame-viewer/capability.md` if the rendering differs from the plan).
