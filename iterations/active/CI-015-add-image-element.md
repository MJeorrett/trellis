# Iteration CI-015: Add Image Element

**Target Capability:** `/capabilities/trellis-ast/capability.md`

## User Story
As a Trellis user or AI agent, I want an `Image` element that is drawn as a `Box` with an X through it and has no children, so that I can mark where a picture goes in a wire frame, and I want to give it an `aspect-ratio` (e.g. `aspect-ratio=1:1` for a square) so that I can show its shape.

Read the `CI-015` entries in the Product and Technical Decisions of the target capability, and the `CI-015 Image (planned)` and `CI-015 Image aspect ratio` entries in `/capabilities/wire-frame-viewer/capability.md`, before starting. They define the behaviour (no text, no children, `width`, `link-to` and `aspect-ratio` allowed, aspect ratio `1:1` by default, minimum width 6rem), the syntax and its exact errors, and the representation.

## Acceptance Criteria
1. `NodeTypeSchema` in `src/schema/ast.ts` is `z.enum(["Box", "Text", "Row", "BoxRow", "Spacer", "Image"])`. `AstSchema` rejects (via `superRefine`) an `Image` with non-empty `text`, any `children`, a `font` or a `fontSize`, and accepts `linkTo`, `width` and `aspectRatio`. `src/schema/ast.test.ts` covers a valid `Image` (in a page, `Box`, `Row` and `BoxRow`, with and without `linkTo` and `width`) and each rejection.
2. `parseSyntax` in `src/syntax/parse.ts` accepts `Image` (case-sensitive; `image` is still an unknown type error with its line number) and produces `{ type: "Image", text: "", children: [] }`, plus `linkTo`, `width` and `aspectRatio` when written (`Image link-to=home width=4`, in either order).
3. `parseSyntax` reports these fail-fast errors with the 1-based line number: `Line <n>: Image cannot have text` (`Image "x"`; `Image ""` is accepted), `Line <n>: Image cannot have children` (reported on the child's line), `Line <n>: Image cannot have font`, `Line <n>: Image cannot have font-size` and `Line <n>: Image cannot have id`. The unknown-type message is `Unknown type "<name>" (expected Box or Text or Row or BoxRow or Spacer or Image)`, and existing tests that assert it are updated.
4. `src/syntax/parse.test.ts` covers: an `Image` as a child of a `Page`, a `Box` and a `Row`, an `Image` with `width` and `link-to`, and every error above with its exact message.
5. `WireframeNode` in `src/viewer/wireframe.tsx` renders `Image` as a bordered, sketchy `Box`-like `div` with `data-node-type="Image"`, `min-w-24` (and, as criterion 9 says, an aspect ratio instead of a minimum height), and an inline `svg` X (two corner-to-corner `line`s, `preserveAspectRatio="none"`, `pointer-events-none`) and no text or children. Link attributes and `width` slot styles apply as for a `Box`. Other types render as before.
6. `src/viewer/wireframe.test.tsx` verifies (with `renderToStaticMarkup`, as in the existing tests) that an `Image` renders with the border classes, `data-node-type="Image"`, `min-w-24`, the default `aspect-ratio:1 / 1` style and the X `svg` with two `line`s, that a linked `Image` gets the link attributes, and that an `Image` in a `Row` with `width` gets the slot style.
7. Aspect ratio schema: `src/schema/ast.ts` exports `ASPECT_RATIO_PATTERN` and `AspectRatioSchema` (a string `W:H` with each part a whole number from 1 to 99, no sign or leading zero), and `AstNodeSchema` has an optional `aspectRatio`, omitted when not written. `AstSchema` rejects an `aspectRatio` on any node that is not an `Image` (`<Type> cannot have aspect-ratio`). `ast.test.ts` covers valid and invalid values and the rejection on other types.
8. Aspect ratio parser: `parseSyntax` accepts `aspect-ratio=W:H` on `Image` only, combined with `link-to` and `width` in any order, and writes `aspectRatio` (as written, e.g. `"16:9"`) to the node only when present. Errors (fail-fast, with line number): `Attribute "aspect-ratio" requires a ratio such as 16:9 (whole numbers from 1 to 99)` for a missing or invalid value (`aspect-ratio=`, `1`, `1:`, `:1`, `0:1`, `1:0`, `100:1`, `01:1`, `1:1:1`, `1.5:1`, `a:b`), `Duplicate attribute "aspect-ratio"`, and `<Type> cannot have aspect-ratio` for every other type (checked before the value, as for the other attributes). `parse.test.ts` covers each.
9. Aspect ratio viewer: an `Image` always gets the inline style `aspect-ratio: W / H` and `min-w-24`, and never `min-h-24` (so the ratio holds). The ratio is the written `aspectRatio`, or `1:1` when none is written (the default is applied by the viewer only and is not written to the AST, so an `Image` without one renders identically to one with `aspect-ratio=1:1`). An `Image` that is a direct child of a `Row` or `BoxRow` also gets `self-start`, so that the row's stretching does not distort it. `wireframe.test.tsx` covers the style, the `1:1` default, the classes and `self-start` in and outside a row.
10. `pnpm test` passes and `pnpm build` succeeds.
11. Updates `README.md` (syntax section: `Type` includes `Image` and its `aspect-ratio`, describing it and its rules) and the Syntax and Data Dictionary sections of the target capability (`Type` list, grammar, `type` entry, `aspectRatio` entry), and logs the implementation decisions in the target capability's Product Decisions or Technical Decisions (and a note in `/capabilities/wire-frame-viewer/capability.md` if the rendering differs from the plan).
