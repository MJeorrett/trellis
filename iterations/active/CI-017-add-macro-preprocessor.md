# Iteration CI-017: Add macro preprocessor

**Target Capability:** `/capabilities/macros/capability.md`

## User Story
As a Trellis author, I want to define a macro with `Def` and use it in my wire frame source, so that a repeated structure is written once and expanded to core primitives before the source is parsed. Read all the CI-017 decisions in the capability first (Product Decisions and Technical Decisions); where one supersedes another (`CI-017 Parameters can be used anywhere`, `CI-017 Argument values`, `CI-017 Substitution`) the later entry wins. The built-in macros (`Field`, `Card`, `NavTabs`, `FieldList`) are out of scope.

## Acceptance Criteria
1. `src/web/syntax/macros.ts` exports `expandMacros(source)` returning `{ ok: true; source; origins } | { ok: false; error }` as in `CI-017 Module layout (planned)`, with `MacroNameSchema`, `ParamNameSchema` and `MacroDefinitionSchema` (Zod) used internally. A source with no `Def` and no macro use expands to exactly the same text, with `origins[i].line === i + 1`.
2. `Def <Name> $p1 $p2` at indent 0 with a 2-space indented body defines a macro, and the `Def` block produces no output. A `Def` may appear before, between and after pages, a macro may have no parameters, and a body may have several first-level lines.
3. Using a macro as `<Name> key=value ...` replaces the line with the body, re-indented to the use line's indentation. An argument is a quoted string or a bare value, and its surrounding quotes are stripped when stored (`label="Test label"` gives `$label` = `Test label`, `font=bold` gives `$font` = `bold`). Every `$name` on a body line is replaced by the stored value wherever it appears (inside the quotes of the text, as an attribute value, as an attribute key or as the type), so a body writes `Text "$label" font=$font` and gets `Text "Test label" font=bold`, never a double-quoted value. A value that itself contains `$name` is not substituted again. Arguments may be in any order, and `""` is a valid argument. The specification's example (`Field label="First Name" value="Please enter First Name..." font=bold` inside a `Page`, with the body `Text "$label" font=$font` and `Box "$value"` in a `BoxRow`) expands to the plain `BoxRow`, and `compileSyntax` gives the same AST as writing it by hand.
4. A macro body may use macros defined above it (nested expansion, including re-indentation at each level, and passing an outer parameter on as in `Field label="$title"`). A macro using itself or one defined below it is not expanded (the use is left as an unknown type for the core parser).
5. Every error in `CI-017 Errors (planned)` is reported with its exact message and the 1-based line number of the source as written (`Line <n>: <message>`), fail-fast: `Def must not be indented`, `Def requires a name`, invalid and reserved macro names, `Duplicate macro`, invalid and duplicate parameters, `Macro "<name>" has an empty body`, `Unknown parameter` (any undeclared `$name` on a body line, including inside quotes), missing, unknown, duplicate and invalid arguments (`Invalid argument "<token>" (expected name=value or name="value")`) and `Macro "<name>" cannot have children`. The error `Parameter "$<name>" can only be used as text` does not exist (see `CI-017 Parameters can be used anywhere (planned)`).
6. `src/web/syntax/compile.ts` exports `compileSyntax(source): ParseResult` that runs `expandMacros` then `parseSyntax` and maps a core error's `Line <n>:` back to the original line, appending ` (in macro "<Name>")` when the line came from a macro body. A macro-free source gives exactly the same result and errors as `parseSyntax` (including the seeded sample wire frames).
7. `parseSyntax` and `src/web/schema/ast.ts` are not changed, and a test shows that `parseSyntax` alone still rejects a macro use as an unknown type (it is unaware of macros).
8. `WireframeEditor` (`src/web/viewer/wireframe-editor.tsx`) parses with `compileSyntax`, so a source with a `Def` and macro uses renders its expansion in the preview, and an error is shown with the line number of the written source (and so under the right tab by `locateParseError`). Switching tabs, `+` and saving behave as before.
9. Tests: `macros.test.ts` (expansion, quote stripping, parameters in text and attribute positions, indentation, nesting, `origins`, every error message), `compile.test.ts` (the example, error line mapping with and without a macro, macro-free equality with `parseSyntax`) and a `wireframe-editor.test.tsx` case rendering a macro source (`renderToStaticMarkup`). `pnpm test` and `pnpm build` succeed.
10. Update `README.md` with a one-line mention that wire frame source supports `Def` macros if behaviour changes (keep it brief, per the repo rule), and log the decisions made while implementing (confirming or amending the `(planned)` entries) in the `macros` capability's Product Decisions or Technical Decisions.
