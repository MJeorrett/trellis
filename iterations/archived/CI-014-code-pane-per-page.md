# Iteration CI-014: Code Pane Per Page

**Target Capability:** `/capabilities/features/capability.md`

## User Story
As a Trellis user, I want the feature details page to show a separate code pane for each page of the wire frame (with its title and id, and a button to add a page), so that I can edit one page at a time instead of one long source text.

Read the `CI-014` entries in the Product Decisions, Technical Decisions and Data Dictionary of the target capability before starting, and the `CI-014` entry in `/capabilities/wire-frame-viewer/capability.md`. They define the panes, adding a page, where syntax errors show, the split/join functions and the updated `Features list` sample.

## Acceptance Criteria
1. `src/viewer/source-pages.ts` exports `SourcePage` (`title`, `id`, `content`), `splitSourcePages(source)`, `joinSourcePages(pages)` and `locateParseError(pages, error)` as described in `CI-014 Source pages (planned)`. They are pure and DOM-free. The stored source stays one string (`Feature.wireframe` and `src/features/api.ts` are unchanged).
2. `splitSourcePages` gives one pane per `Page` line at indent 0, in source order, reading its title and optional `id` (no `id` gives `""`); the empty source gives one page with empty title, id and content; text before the first `Page` line goes into the first page's content. It removes up to 2 leading spaces from each line of a page's content, so a pane's nodes start at column 0 and its content never contains the `Page` line. `joinSourcePages(splitSourcePages(source))` parses with `parseSyntax` to the same AST as `source` for the three seeded wire frames and for the empty source.
3. `joinSourcePages` builds each header as `Page "<title>"`, adding ` id=<id>` only when the id is not empty (the id is optional), then the page's content with 2 spaces added to every non-blank line (blank lines stay empty), and the result parses with `parseSyntax` for valid inputs.
4. `locateParseError` maps a parser error to the page it belongs to: a content error as the page position plus a `Line <n>: <message>` where `n` counts within that page's content (1 = first content line), and an error on a page's own line (for example `Duplicate page id "<id>"` on the second page, or an unwritable title) as the page position plus the bare message. A `Page cannot be nested` error is shown with the message `Page cannot be written here, it is created from the title and id`. A source without errors gives no location.
5. `src/viewer/wireframe-editor.tsx`: `WireframeEditor` keeps its props (`source`, `onSourceChange`). Its "Wire frame source" card shows one pane per page: a bordered box with a header row (`Page:` title input, `Id:` optional id input) and a monospace text area with the page's content from column 0 (never a `Page` line), then a centred `+ Add Page` button. Title input, id input and text area have `aria-label`s naming their page (`Page 1 title`, `Page 1 id`, `Page 1 source`). Every change calls `onSourceChange` with the joined source, and typing a `Page` line in a text area never creates a pane. The "Wire frame" card, page tabs, links and toasts are unchanged.
6. `+ Add Page` calls `onSourceChange` with a new last page titled `Page N`, id `page-N` (N = its 1-based position, or the next free number if that id is taken) and empty content. It does not change the selected tab.
7. A syntax error is shown under the pane it belongs to (content errors with the line number counted within the pane, header errors without a line number), not under all the panes. While there is an error the preview still shows `Fix the source to see the wire frame.`
8. `src/features/wireframes/features-list.ts`: the `Feature detail` page's "Wire frame source" pane is replaced by the wireframe given for this iteration: one bordered box per page (`BoxRow` with `Page:`, title box, `Id:`, id box, then the page's source lines as `Text` lines, starting at column 0 as a pane shows them (`Box`, `  Text ...`), unlike the 2-space-indented lines in the original wireframe) for `Log in`/`login` and `Forgot password`/`forgot`, and a last box with a `Row` of `Spacer`, `Box "+ Add Page"`, `Spacer`. The "Wire frame" pane, the other pages and their links are unchanged, the source still parses with `parseSyntax` and the indentation of the shown source lines stays visible in the preview.
9. Tests (`pnpm test`, DOM-free as before): `src/viewer/source-pages.test.ts` covers split (several pages, with and without id, empty source, text before the first page, the 2-space indent removed and never a `Page` line in the content), join (with and without id, empty content, the 2-space indent added, blank lines kept empty), the round trip (same AST) for the seeded wire frames and the empty source, a `Page` line typed in a pane staying in that pane and giving the `Page cannot be written here, it is created from the title and id` error, and `locateParseError` (content error, header error, no error, error on a later page). `renderToStaticMarkup` tests on `WireframeEditor` verify one pane per page with its title, id and content, the `+ Add Page` button, the error shown under the right pane only, and that a single-page and the empty source show one pane. A test checks that the `features-list.ts` source parses and that its `Feature detail` page contains the `+ Add Page` box. Existing tests are updated where they referenced the single source text area.
10. `pnpm test`, `pnpm typecheck` and `pnpm build` pass.
11. Updates `README.md` if it describes the source editor (per-page panes, `+ Add Page`), and logs the implementation decisions in the Product Decisions or Technical Decisions of `/capabilities/features/capability.md` and, if the editor behaviour changed from what is planned, `/capabilities/wire-frame-viewer/capability.md` (the `(planned)` entries are confirmed or amended by `CI-014 ... implementation` entries; old entries stay as history).
