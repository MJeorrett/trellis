# Iteration CI-024: Add Syntax Highlighting

**Target Capability:** `/capabilities/syntax-highlighting/capability.md`

## User Story
As a Trellis author or AI agent, I want the wire frame source in every code editor (the feature source tabs, the Macros page and the Examples page) to be syntax highlighted, with line numbers, using CodeMirror 6, so that I can find the line of an error and tell comments, strings, pointers, parameters, keywords, types and attributes apart at a glance.

Read all `CI-024` entries in the Product and Technical Decisions of the target capability first. For the syntax being highlighted read the Syntax section of `/capabilities/trellis-ast/capability.md` (including `CI-023 Comments (planned)`) and the Syntax section of `/capabilities/macros/capability.md`. For the pointer form read `/capabilities/data-references/capability.md`.

## Acceptance Criteria
1. The CodeMirror 6 packages `@codemirror/state`, `@codemirror/view`, `@codemirror/language` and `@codemirror/commands` are added with `pnpm add` (no `codemirror` bundle, no `basicSetup`, no other package manager).
2. `src/web/syntax/highlight.ts` exports `trellisLanguage` (a `StreamLanguage`), `tokenizeLine(line)` and `trellisHighlighter`, with the token order and patterns of `CI-024 Language module (planned)`. It imports nothing from React or the DOM.
3. `src/web/syntax/highlight.test.ts` covers `tokenizeLine` (the same `token` function the language uses), at least: `# note` is one `comment`; `#` alone is a `comment`; an indented `  # note` and `Box "# x"` are not comments (the `#` has no token); `Page "Log in" id=login` gives `typeName`, `string`, `attributeName` for `id=` and plain `login`; `width=3` gives `attributeName` and `number`; `link-to=forgot` and `font-size=lg` give `attributeName`; `Def Field $label $value` gives `keyword`, `typeName`, `variableName`, `variableName`; `Each $items as=item` gives `keyword`, `variableName`, `attributeName`; `Text "$1"` is one `string`; `PageTitle $1` and `Text $item.title` give `variableName` for the whole reference; `$12` is not a parameter reference; `TableColumn @User.FirstName.label width=4` gives `typeName`, `variableName.special`, `attributeName`, `number`; `item.title="Hi"` gives `attributeName` for `item.title=` and `string`; `Spacer`, `BoxRow` and a macro name give `typeName`; an unterminated quote does not throw and the rest of the line still tokenises; an empty line gives no pieces.
4. `src/web/index.css` defines the colours of the `tok-*` classes for the light and the `.dark` theme: comment dimmed, and string, pointer, parameter, keyword, type, attribute and number all distinguishable, with pointers and parameters different from each other and from strings.
5. `src/web/components/code-editor.tsx` exports `CodeEditor` with the props of `CI-024 CodeEditor component (planned)`: one `EditorView` created on mount and destroyed on unmount, `value` and `onChange` controlled without a loop (programmatic replacement does not call `onChange`), `readOnly` (selectable and copyable, no input, no focus ring change), a line number gutter (`lineNumbers()` from `@codemirror/view`) starting at 1 in every editor, muted, not selectable and not part of copied text, themed for light and dark, `ariaLabel` set as the accessible name of the editable element, the optional `placeholder`, `lineWrapping` for editable editors only, history (undo and redo), the default keymap without `Tab` capture, Enter keeping the previous line's indentation, and a theme that uses the app's CSS variables and the `Textarea`'s focus ring.
6. `CodeEditor`'s static markup (`renderToStaticMarkup`) contains its container with the `ariaLabel` and, in that first render, the value as text. `src/web/components/code-editor.test.tsx` covers: the label, the value text, an empty value, a read-only editor, and that `className` is applied.
7. `WireframeEditor` uses `CodeEditor` for the selected page's source (`Page N source`, the `Page "Page 1" id=page-1` placeholder), with the card layout, the fixed tabs, the error message above it, adding pages and every edit being saved exactly as before; switching tabs shows the selected page's text. `MacroEditor` uses `CodeEditor` for `Macros source` filling its card. The `Textarea` is no longer used by either.
8. `ExampleSection` in `src/web/pages/examples.tsx` shows each example's source in a read-only, highlighted `CodeEditor` labelled `<title> source`, scrolling sideways when a line is long, beside the preview as before; an example with an error still shows the `role="alert"` message in place of the preview.
9. The existing tests that read a `textarea` are updated to read the editor's container instead: `src/web/viewer/wireframe-editor.test.tsx`, `src/web/macros/macro-editor.test.tsx` and `src/web/pages/examples.test.tsx` (including the check that the source and its comments are shown and that no `textarea` remains in those components). The other tests still pass unchanged. The `Add feature` dialog still uses its `Textarea`.
10. `pnpm test`, `pnpm typecheck` and `pnpm build` pass.
11. Checked in a browser with a feature's source tabs, the Macros page and the Examples page: highlighting and line numbers show (a wrapped line is numbered once, the numbers match the `Line <n>:` of an error in that text, and copying text from a read-only example does not copy the numbers), typing, undo and redo work, a tab switch shows the right text, edits are still saved and reloaded, the preview and error messages update as before, and both light and dark themes are readable.
12. Updates `README.md` (features overview only: syntax highlighted editors, keeping it brief) and logs the implementation decisions in the target capability's Product Decisions or Technical Decisions (confirming or amending each `CI-024 ... (planned)` entry that differs from the plan).
