# Iteration CI-008: Add Feature Details Page

**Target Capability:** `/capabilities/features/capability.md`

## User Story
As a Trellis user, I want each feature to have a details page that holds its own wire frame source editor and preview, replacing the separate wire frame demo page, so that I can see and edit the wire frame of every feature.

Read the `CI-008` entries in the Product Decisions, Technical Decisions and Data Dictionary of the target capability before starting, and the `CI-008` entries in `/capabilities/wire-frame-viewer/capability.md`. They define the route, the unknown-feature behaviour, how a wire frame is stored per feature, the source files and the components.

## Acceptance Criteria
1. `src/features/schema.ts`: `FeatureSchema` gets `wireframe: z.string()` (`""` allowed). `CreateFeatureInputSchema` is unchanged.
2. `src/features/api.ts` exports `getFeature(id)` (resolves the feature, or `undefined` for an unknown id) and `updateFeatureWireframe(id, wireframe)` (resolves the updated feature, rejects with an `Error` for an unknown id), in-memory, delayed and returning copies like the existing functions. `createFeature` sets `wireframe: ""`. `resetMockFeatures()` also restores the seeded wire frames.
3. Each of the three seeded features has its wire frame source in its own file in `src/features/wireframes/`, one `.ts` file per feature exporting a single source string, imported by the seed in `src/features/api.ts`. The first is the Login Form sample moved from `src/viewer/sample.ts`, which is deleted along with its remaining imports; the other two are samples for `Page links` (two pages linking to each other) and `Features list`. Every sample parses successfully with `parseSyntax`.
4. `src/viewer/wireframe-editor.tsx` exports `WireframeEditor` (props `source`, `onSourceChange`) containing the source editor, inline parse errors and `PageTabs` preview that `src/pages/wireframe-demo.tsx` has today, with unchanged behaviour (including page links and the not-found toast).
5. `src/pages/feature-details.tsx` is the page for `/features/:id`. It loads the feature with `getFeature`, shows its name as the heading with a link back to `/features`, its description when it is not `""`, and the `WireframeEditor` for the feature's wire frame source. Every edit updates the editor immediately and is saved with `updateFeatureWireframe`, with no save button, so the edit is still there when navigating away and back (until reload). For an unknown id it shows `Feature not found` and a link back to `/features`. It shows nothing until the mock API has answered (no loading state).
6. `src/features/feature-list.tsx` renders each feature's name as a react-router `Link` to `/features/<id>`. The description and the rest of the list are unchanged.
7. `src/pages/wireframe-demo.tsx` is deleted. `src/App.tsx` has the routes `/features`, `/features/:id`, and `/` and any unknown path (including `/wireframe-demo`) redirecting to `/features`.
8. `src/components/top-nav.tsx` has a single item, `Features`, which is current (`aria-current="page"`) on `/features` and on `/features/:id`. The `Wireframe` item is removed.
9. Tests (`pnpm test`, DOM-free as before): `schema.test.ts` covers `wireframe` (required, `""` allowed). `api.test.ts` covers `getFeature` (known and unknown id), `updateFeatureWireframe` (updates, persists in the next `getFeature` and `listFeatures`, unknown id rejects, returns copies), `createFeature` returning `wireframe: ""` and `resetMockFeatures()` restoring seeded wire frames. A test checks that every seeded feature's wire frame parses with `parseSyntax` and that the seeded wire frames are different from each other. `renderToStaticMarkup` tests with `MemoryRouter` verify that the list links to `/features/<id>`, that `/features/:id` renders the `WireframeEditor` (editor and preview) for a known feature, that the top nav has only `Features` and marks it current on both routes, and that `/wireframe-demo` and `/` match a `Navigate` to `/features` in `appRoutes`. Existing tests that referenced the demo page or `sampleSource` are updated or removed.
10. `pnpm test`, `pnpm typecheck` and `pnpm build` pass.
11. Updates `README.md` (routes `/features` and `/features/:id`, the wire frame editor being on the feature details page, that `/wireframe-demo` no longer exists, and the demo link and screenshot), and logs the implementation decisions in the Product Decisions or Technical Decisions of `/capabilities/features/capability.md` and, for the editor and route change, `/capabilities/wire-frame-viewer/capability.md` (the `(planned)` entries are confirmed or amended by `CI-008 ... implementation` entries; old entries stay as history).
