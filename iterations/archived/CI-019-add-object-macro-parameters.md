# Iteration CI-019: Add Object Macro Parameters

**Target Capability:** `/capabilities/macros/capability.md`

## User Story
As a Trellis author, I want a macro parameter that holds several named fields (`Def Card $item=title|description|id`, used as `$item.title` in the body) so that I can pass a whole record to a macro as one argument instead of declaring a separate parameter for each value.

Read the `CI-019` entries in the Product Decisions, Technical Decisions, Syntax and Data Dictionary of the target capability before starting, and the `CI-017` and unlabeled argument entries they extend (`CI-017 Parameters can be used anywhere (planned)`, `CI-017 Argument values (planned)`, `Unlabeled argument $1`, `CI-017 Preprocessor implementation`).

## Acceptance Criteria
1. `src/web/syntax/macros.ts`: a `Def` parameter token `$name=field|field|...` declares an object parameter. `MacroDefinitionSchema` (still a `z.strictObject`) gains `objects`, a map from parameter name to its non-empty list of field names (`FieldNameSchema`, same pattern as `ParamNameSchema`), empty for a macro with no object parameters; `params` still lists every parameter, plain or object, in order. Plain parameters, mixed `Def` lines and macros without object parameters behave exactly as before.
2. In a body, `$item.title` is replaced by the value of that field, anywhere a `$name` may appear (text, attribute value or key, type), and the result is never double-quoted. For a plain parameter `$label.x` still gives the value followed by `.x`.
3. Both forms of use give the same expansion. Dotted: `Card item.title="Hi" item.description="Text" item.id="1"` (any order, each field once). Piped: `Card item="Hi"|"Text"|"1"`, with the values in the declared field order, each quoted or bare (a bare value has no spaces, `"` or `|`), a quoted value may contain `|` and spaces, `""` is valid, and the quotes are stripped when stored. Both combine with the unlabeled `$1` argument and plain named arguments.
4. The new errors are produced fail-fast, prefixed `Line <n>: `, with exactly these messages: `Invalid parameter "<token>" (expected $name or $name=field|field)` (this replaces the old `expected $name` wording for every invalid parameter token, including `Def A $1`); `Duplicate field "<field>" in parameter "$<name>"`; `Parameter "$<name>" is an object (use $<name>.<field>)`; `Unknown field "<field>" on parameter "$<name>"`; `Missing argument "<name>.<field>" for macro "<macro>"`; `Unknown argument "<name>.<field>" for macro "<macro>"`; `Duplicate argument "<name>.<field>"` (given twice or by both forms); `Parameter "<name>" expects <n> values but got <m>`; and `Invalid argument "<token>" (expected name=value or name="value")` for a malformed piped value (e.g. `item=a||b`). Errors from the expansion keep the line mapping of `CI-017 Error lines (planned)`.
5. `parseSyntax`, `compileSyntax`, the AST schema and the line mapping are unchanged, and a source without object parameters is parsed exactly as before (including a source with no `Def`, which is still returned as the very same string).
6. The seed of the global macros (`seedMacrosSource` in `src/web/macros/api.ts`) also defines `Def Card $item=title|description|id` (a `Box` with the title in bold, the description and the id as `Text` lines), and its `Try it` page shows two cards, one in each argument form, besides the existing `Field` use. `Field` is unchanged. The seed compiles without error, and no seeded feature wire frame defines `Card`.
7. Tests (`pnpm test`, DOM-free as before): `src/web/syntax/macros.test.ts` gets an `object parameters` group covering the `Def` parsing (one field, several fields, mixed with plain parameters, an object parameter beside `$1`), body substitution (a field used several times, in an attribute value, in a quoted text, the `$label.x` plain-parameter case, passing a field on to a nested macro as a plain argument such as `Inner label="$item.title"`), both argument forms and their equivalence (including quoted, bare, empty and `|` containing values and any order of the dotted form), and every error in criterion 4 with its exact message and line. `src/web/macros/api.test.ts` and `src/web/macros/macro-editor.test.tsx` are updated for the new seed (it compiles and the preview shows the cards). Existing tests that assert the old `expected $name` wording are updated.
8. `pnpm test`, `pnpm typecheck` and `pnpm build` pass.
9. Updates `README.md` only if it describes macro parameters (keep it a short feature mention), and logs the implementation decisions in the Product Decisions or Technical Decisions of `/capabilities/macros/capability.md` (the `(planned)` `CI-019` entries are confirmed or amended by `CI-019 ... implementation` entries; old entries stay as history).
