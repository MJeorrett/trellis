# Iteration CI-023: Add Examples Page and Comments

**Target Capability:** `/capabilities/examples/capability.md`

## User Story
As a Trellis author or AI agent, I want an `Examples` page in the top nav that shows a working, annotated example of every element and feature of the syntax, and I want `#` comment lines in the syntax so that those examples (and my own wire frames) can be annotated.

Read the `CI-023` entries in the Product and Technical Decisions of the target capability first. Then read `CI-023 Comments (planned)` and `CI-023 Comments implementation (planned)` in `/capabilities/trellis-ast/capability.md`, `CI-023 Comments (planned)` in `/capabilities/macros/capability.md`, and `CI-023 Examples nav item (planned)` and `CI-023 Comments in page tabs (planned)` in `/capabilities/features/capability.md`. They define the comment rules, the page, the sections, the coverage and the self-contained data.

## Acceptance Criteria
1. A shared pure helper `isCommentLine(line)` (true when the line's first character is `#`) is exported from the syntax code (for example `src/web/syntax/comments.ts`) and used by both `expandMacros` and `parseSyntax`. `src/web/syntax/comments.test.ts` covers: `# note` is a comment; `#` alone is a comment; `  # note` (indented), `Box "# x"` and an empty line are not.
2. `parseSyntax` ignores comment lines exactly like blank lines: a comment between nodes, before the first `Page`, after the last line, between pages and at any depth does not change the AST, does not affect indentation of the lines around it, and keeps the 1-based line numbers of errors as written (the line after a comment reports its own line number). An indented `# note` is still an unknown-type error with its line number. `src/web/syntax/parse.test.ts` covers each case, plus a source made only of comments, which is the blank page.
3. `expandMacros` ignores comment lines: a column-0 `#` line inside a `Def` body does not end the body and is not part of it, a `#` line between a `Def` and its use is ignored, a `#` line is never treated as a macro use or a `Def`, and an indented `#` line in a body stays a body line. Errors keep the line numbers of the source as written, and `compileSyntax` maps core errors found after a comment to the right original line. A source with no comment, `Def` or macro use is still returned as the very same string. `src/web/syntax/macros.test.ts` and `compile.test.ts` cover these cases.
4. In a feature's source tabs a comment above a `Page` line stays at the end of the previous page's text (the tab names and the `+` behaviour are unchanged). `src/web/viewer/source-pages.test.ts` covers it, and `src/web/viewer/wireframe-editor.test.tsx` shows that a source with comments previews correctly.
5. `src/web/examples/examples.ts` exports `exampleDataDictionary` (a few `DataDictionaryRow`s, at least `User`/`FirstName` and `User`/`Email`, with labels and mock values, one with several `;` separated mock values) and `examples` (`{ title, source }[]`), validated by an `ExampleSchema` (`z.strictObject`, non-empty `title`), in the order of `CI-023 Coverage (planned)`.
6. The examples cover, each with its own annotated source (notes written as `#` comment lines): `Page`, `Box`, `Text`, `Row`, `BoxRow`, `Spacer`, `Image`, `Table` with `TableColumn` (literal and pointer columns); page `id` with `link-to` between two pages; `width`, `font`, `font-size`, `aspect-ratio`, nesting; macros (`Def` with parameters, `$1`, an object parameter, a list parameter with `Each`); data references (a pointer on a node, a pointer macro argument, a pointer column); and comments themselves. Examples that use macros define their own `Def`s.
7. `src/web/examples/examples.test.ts` verifies that every example compiles with `compileSyntax(source, undefined, exampleDataDictionary)` without an error, that every title is unique, that every example contains at least one comment line, and that the examples together use every type in `NodeTypeSchema.options`.
8. `ExamplesPage` and `ExamplesView` in `src/web/pages/examples.tsx` render an `Examples` heading and, per example, a section with its title, the read-only source text and the compiled preview with page tabs (reusing `PageTabs`, with links working as in `WireframeEditor`), side by side on a wide window and stacked on a narrow one. An example with an error shows the message instead of the preview. A final section, `Data dictionary used by these examples`, shows `exampleDataDictionary` as a read-only table (entity, field, data type, label, mock values). The page does not wait for the user's macros or data dictionary, uses none of them, and scrolls inside the routed content area.
9. `src/web/App.tsx` adds `EXAMPLES_PATH` (`/examples`) to `appRoutes` and an `Examples` item after `Macros` in `navItems`, highlighted on `/examples` only; `/examples` no longer redirects. `src/web/pages/examples.test.tsx` and the nav and route checks in `src/web/pages/features.test.tsx` (`renderToStaticMarkup` and `matchRoutes`, as elsewhere) cover the nav items, the route, one section per example, the source text and comments being shown, the data dictionary section and the error case (with a deliberately broken example passed to `ExamplesView`).
10. `pnpm test` and `pnpm build` pass.
11. Updates `README.md` (features overview only: the Examples page and `#` comments, keeping it brief), the Syntax section of `/capabilities/trellis-ast/capability.md` (comment lines in the grammar, with a short annotated example) and the Syntax section of `/capabilities/macros/capability.md` if the grammar changes, and logs the implementation decisions in the target capability's Product Decisions or Technical Decisions (with notes in `/capabilities/trellis-ast/capability.md`, `/capabilities/macros/capability.md` and `/capabilities/features/capability.md` if the behaviour differs from the plan).
