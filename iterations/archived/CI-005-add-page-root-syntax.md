# Iteration CI-005: Add Page Root Syntax

**Target Capability:** `/capabilities/trellis-ast/capability.md`

## User Story
As a Trellis user or AI agent, I want a `Page` component that describes one complete page of the wire frame, is the only root-level component and takes a mandatory title, and a preview that lets me switch between pages, so that I can describe a multi-page flow (e.g. Log in and Forgot password) in a single source.

Read the `CI-005` entries in the Product and Technical Decisions of the target capability before starting, and the `CI-005 Pages` entry in `/capabilities/wire-frame-viewer/capability.md`. They define the behaviour (root-only, no nesting, Row/Box/Text children, mandatory title, multiple pages, errors, blank source, tabs) and the representation (`{ pages: Page[] }`, a separate `PageSchema`). Also update the Syntax and Data Dictionary sections, which already describe the new state.

## Acceptance Criteria
1. `src/schema/ast.ts` exports `PageSchema` (`z.strictObject({ title, children })`, children being `AstNodeSchema[]`), a `Page` type, and `AstSchema` as `z.strictObject({ pages: z.array(PageSchema).min(1) })`. `NodeTypeSchema` and `AstNodeSchema` are unchanged. `Ast` and `AstNode` remain exported.
2. `src/schema/ast.test.ts` is updated so that: a single page and several pages validate; a page with an empty title (`""`) and with no children validates; a page without a `title` key is rejected; an empty `pages` array is rejected; a `Page` nested inside a node's `children` (or a `type: "Page"` node) is rejected; a bare node as the root is rejected; unknown keys on a page are rejected.
3. `parseSyntax` in `src/syntax/parse.ts` parses `Page "Title"`, `Page ""` and `Page "Title"` with nested children into `{ pages: [...] }`. Multiple indent-0 `Page` nodes become multiple pages in source order. Empty or whitespace-only source parses to `{ pages: [{ title: "", children: [] }] }`.
4. `parseSyntax` reports, fail-fast with a 1-based line number (counting blank lines): an indent-0 node that is not a `Page` (e.g. `Line 1: root node must be Page`); a `Page` at indent greater than 0 (e.g. `Page cannot be nested`); a `Page` without a title (e.g. `Line 3: Page requires a title`); the existing errors (tabs, bad indentation, unterminated string, trailing characters, case-sensitive type names such as `page`) still work. The old "multiple root nodes" error is removed.
5. `src/syntax/parse.test.ts` is updated and covers: every case in criteria 3 and 4 (asserting full ASTs and exact error messages), the old Login Form fixtures wrapped in a `Page`, a `Page` containing `Row`, `Box` and `Text` children, and an unwrapped legacy source (starting with `Box`) being rejected.
6. `src/viewer/sample.ts` is updated to a `Page "Log in"` containing the Login Form, followed by a second `Page "Forgot password"`, and still parses to an AST that passes `AstSchema`.
7. The viewer renders one tab per page (shadcn `tabs`, added with `pnpm dlx shadcn@latest add tabs`) in `src/viewer/` and `App.tsx`: tab labels are the page titles (`Page N` for an empty title), tabs are shown even for one page, the first page is selected initially, only the selected page's content is rendered via `WireframeNode`, and the selection is kept by position across edits, falling back to the last page if its position no longer exists. Parse errors are still shown inline under the text area.
8. A viewer test (`renderToStaticMarkup`, as in `src/viewer/wireframe.test.tsx`; no new test setup) verifies the tab labels (title and `Page N` fallback), that the selected page's content is rendered and the others' is not, and the selection fallback logic (extracted as a pure function if needed so it can be tested without a DOM).
9. `pnpm test` passes and `pnpm build` succeeds.
10. Updates `README.md` (syntax section and example: `Page` as the only root, its optional title, multiple pages, the tabbed preview), and logs the implementation decisions in the Product Decisions or Technical Decisions of `/capabilities/trellis-ast/capability.md` and, for the viewer, `/capabilities/wire-frame-viewer/capability.md` (the `(planned)` entries are confirmed or amended by `CI-005 ... implementation` entries; old entries stay as history).
