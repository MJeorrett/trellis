# Iteration CI-026: Add Shareable Wire Frame Link

**Target Capability:** `/capabilities/share-link/capability.md`

## User Story
As a Trellis user, I want to copy a self-contained link to a feature's wire frames and data dictionary, so that someone else can view them, with a tab per page and no source code, without needing my data.

Read every `CI-026` decision in the target capability first. The data dictionary and the preview are described in `/capabilities/data-dictionary/capability.md` and `/capabilities/wire-frame-viewer/capability.md`.

## Acceptance Criteria
1. `src/web/share/schema.ts` exports `SharedWireframeSchema` (a `z.strictObject` of `v: z.literal(1)`, `name`, `wireframe`, `macros` and `dataDictionary` using `DataDictionaryRowSchema`) and the type `SharedWireframe` derived with `z.infer`.
2. `src/web/share/encode.ts` exports `encodeShare(data)`, `decodeShare(text)` and `buildShareUrl(origin, data)`, using JSON, `CompressionStream("deflate-raw")` and base64url (no new dependency). `buildShareUrl` returns `<origin>/share#d=<data>`. `decodeShare` gives back the same data for what `encodeShare` produced, including non-ASCII text and multi-line sources, and returns `undefined` for an empty string, text that is not base64url, valid base64url that is not compressed data, compressed data that is not JSON, and JSON that does not match the schema. `src/web/share/encode.test.ts` covers each of these.
3. `src/web/share/encode.ts` exports `MAX_SHARE_URL_LENGTH` (30,000), and a pure helper reports whether a link is longer than it. The test covers a link below and above the limit.
4. `src/web/pages/shared.tsx` exports `SharedView` (props: the decoded `SharedWireframe`) and the default `SharedPage`, which reads `location.hash`, decodes it and shows `SharedView`. `SharedView` shows the feature's name as a heading, `PageTabs` with the wire frame compiled by `compileSyntax(wireframe, macros, dataDictionary)` (links between pages work) and a read-only data dictionary table (`Entity`, `Field`, `DataType`, `Label`, `MockValues`) pinned at the bottom above the footer. It never renders a text area, the source, the macros, or an editable control. A compile error is shown in a `role="alert"` `pre` in place of the preview.
5. The shared page has a top bar with a `Trellis` link to `/features` and a footer `Shared by Trellis` with `Trellis` as a link to `/features`. `App` does not render `TopNav` on `/share`, and still does on every other route. `SHARE_PATH` (`/share`) is in `appRoutes`.
6. A `/share` with no hash, or a hash that does not decode, shows `This link is not valid` and the `Trellis` link, with no wire frame or data dictionary.
7. `FeatureDetailsView` shows a `Share link` button in the header row, at the right end next to `Back to features`, when it is given `onShare`. `FeatureDetailsLoader` builds the `SharedWireframe` from the feature's name and wire frame, the loaded macros and the loaded data dictionary, copies `buildShareUrl(window.location.origin, data)` with `navigator.clipboard.writeText` and shows a `Link copied` success toast. A link longer than `MAX_SHARE_URL_LENGTH` still gets copied but the toast warns it may be cut off by some tools. If the clipboard write fails the toast is an error that shows the link. `FeatureNotFound` has no share button.
8. Tests (`renderToStaticMarkup`, as elsewhere): `SharedView` with several pages, a macro-using wire frame and a pointer renders the tabs, the rendered text and the dictionary table, and does not contain the source text or a `textarea`; a broken wire frame shows the alert; the invalid-link view; the bar and footer links; `/share` matches in `appRoutes`; `FeatureDetailsView` shows the `Share link` button only with `onShare`. The click, clipboard and toast themselves are not DOM-tested. Check in a browser that a copied link opens the shared page in a fresh session (no local storage data) and that links between pages work.
9. `pnpm test`, `pnpm typecheck` and `pnpm build` pass.
10. Update `README.md` with a one-line feature mention (and `/share` in the routes list if it has one), and log the implementation decisions in the target capability's Product Decisions or Technical Decisions.
