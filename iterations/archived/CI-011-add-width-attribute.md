# Iteration CI-011: Add Width Attribute

**Target Capability:** `/capabilities/trellis-ast/capability.md`

## User Story
As a Trellis user or AI agent, I want a `width=N` attribute on `Box`, `Text`, `Row` and `Spacer` so that I can set the relative width of items within a `Row` in twelfths (e.g. a `width=3` child and a `width=9` child take 1/4 and 3/4 of the row).

Read the `CI-011` entries in the Product and Technical Decisions of the target capability, and the `CI-011 Width (planned)` entry in `/capabilities/wire-frame-viewer/capability.md`, before starting. They define the meaning (twelfths of the row, no effect outside a `Row`), the default of 3 for children without a width when at least one sibling has one (including a `Spacer`), the valid values, the exact syntax errors and the representation.

## Acceptance Criteria
1. `src/schema/ast.ts` exports `WidthSchema = z.number().int().min(1).max(12)` and `AstNodeSchema` has an optional `width: WidthSchema` (omitted when absent, still a `z.strictObject`). `src/schema/ast.test.ts` covers valid widths 1 and 12 on each node type, rejection of 0, 13, a non-integer and a non-number, and that a `width` key on a `Page` is rejected.
2. `parseSyntax` in `src/syntax/parse.ts` accepts `width=N` on `Box`, `Text`, `Row` and `Spacer` (after the optional quoted text, and together with `link-to` in either order) and produces a numeric `width` on the node only when written. Ids and links are unchanged. A `width` on a node that is not inside a `Row` is valid and kept in the AST.
3. `parseSyntax` reports these fail-fast errors with the 1-based line number: `Line <n>: Page cannot have width`; `Line <n>: Attribute "width" requires a whole number from 1 to 12` for `width=` (missing value), `width=0`, `width=13`, `width=abc`, `width=03`, `width=2.5` and `width=-1`; `Line <n>: Duplicate attribute "width"`; and `Spacer width=2` is accepted while `Spacer link-to=x` still gives `Spacer cannot have link-to`. The unsupported-kind check runs before the value check (`Page "x" width=99` reports `Page cannot have width`).
4. `src/syntax/parse.test.ts` covers: `width` on each of `Box`, `Text`, `Row` and `Spacer` (full AST), `width` combined with `link-to` in both orders, `width` outside a `Row`, text omitted before the attribute (`Box width=3`), and every error above with its exact message.
5. `src/viewer/layout.ts` exports a pure function `rowWidths(children)` returning, for each child, `undefined` when no child has a `width`, otherwise the child's `width` or `3` (a `Spacer` included). `src/viewer/layout.test.ts` covers: no widths, all widths, some widths (defaults to 3), a `Spacer` with and without width in a row with widths, a `Spacer` in a row without widths, and an empty row.
6. `WireframeNode` in `src/viewer/wireframe.tsx` lays out the children of a `Row` that has widths with an inline `flex: 0 0 <basis>` and `min-width: 0` on each child, where the basis is N/12 of the row's inner width minus its gaps; a `Spacer` with a resolved width is a fixed-width empty `div` (no `flex-1`). A `Row` without widths, a `Box`, a `Text`, a `Page`'s children and a `width` outside a `Row` render exactly as before. `src/viewer/wireframe.test.tsx` (with `renderToStaticMarkup`) verifies a row with `width=3` and `width=9` children, a child without a width defaulting to 3 next to one with a width, a `Spacer` in a row with widths (no `flex-1`), a `Spacer` in a row without widths (still `flex-1`), and that a `width` on a `Box` directly in a `Page` or `Box` adds no layout style.
7. `pnpm test` passes and `pnpm build` succeeds.
8. Updates `README.md` (the syntax section: `width` attribute, its values, the default and its effect only inside a `Row`) and the Syntax (grammar and example) and Data Dictionary (`width`) sections of the target capability, and logs the implementation decisions in the target capability's Product Decisions or Technical Decisions (and a note in `/capabilities/wire-frame-viewer/capability.md` if the rendering differs from the plan).
