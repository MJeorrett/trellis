# Iteration CI-006: Add Page Links

**Target Capability:** `/capabilities/trellis-ast/capability.md`

## User Story
As a Trellis user or AI agent, I want to give pages an `id` and make `Box` and `Text` components link to a page with `link-to`, and have the preview show them as clickable links that open the target page, so that I can wireframe navigation between pages (e.g. Log in and Forgot password).

Read the `CI-006` entries in the Product and Technical Decisions of the target capability before starting, and the `CI-006` entries in `/capabilities/wire-frame-viewer/capability.md`. They define the attribute syntax (`key=value` after the optional text), `id` on `Page` only, `link-to` on `Box` and `Text` only, unique page ids, unvalidated link targets, the pointer cursor, the click behaviour and the toast for unknown targets. The Syntax and Data Dictionary sections already describe the new state.

## Acceptance Criteria
1. `src/schema/ast.ts`: `PageSchema` gains an optional `id` and `AstNodeSchema` an optional `linkTo` (both non-empty strings matching `[A-Za-z0-9_-]+`, keys omitted when absent, schemas still `z.strictObject`). `AstSchema` rejects duplicate page ids. Existing ASTs without these keys still validate.
2. `src/schema/ast.test.ts` covers: a page with an `id`; a node with `linkTo` (nested too); an empty or invalid-pattern `id`/`linkTo` rejected; duplicate page ids rejected; pages without ids (several) still valid; unknown keys still rejected.
3. `parseSyntax` (`src/syntax/parse.ts`) parses `Page "Title" id=my-id` into a page with `id`, and `Box`/`Text` lines with `link-to=target` into nodes with `linkTo`, with and without text (`Text "My Link" link-to=test-id` and `Box link-to=test-id`). Lines without attributes produce the same AST as before (no `id`/`linkTo` keys). A link to a non-existent page id is accepted.
4. `parseSyntax` reports, fail-fast with a 1-based line number and exact messages as defined in the capability: unknown attribute key, duplicated key, missing or invalid value (e.g. `id=`, `id=a b`, `id=a.b`), `id` on `Box`/`Text`/`Row`, `link-to` on `Page` and on `Row`, and a duplicate page id (reported at the second page). Existing errors (tabs, bad indentation, unterminated string, trailing characters, `Page requires a title`, etc.) still work unchanged.
5. `src/syntax/parse.test.ts` covers every case in criteria 3 and 4 (full ASTs and exact error messages), plus an attribute after an unterminated or closed string, and that the previous fixtures still parse to the same ASTs.
6. `src/viewer/wireframe.tsx`: `WireframeNode` accepts an optional `onLink` prop (passed to children). A node with `linkTo` has `cursor-pointer`, `data-link-to`, `role="link"`, `tabIndex={0}`, calls `onLink(linkTo)` on click and on Enter, and stops propagation so only the innermost link fires. Nodes without `linkTo` have none of these.
7. `src/viewer/pages.tsx`: a pure `findPageIndexById(pages, id)` returns the page's position or `undefined`. `PageTabs` passes an `onLink` that selects the target page (via `onSelect`) when the id exists and otherwise leaves the selection unchanged and shows a toast `Page "<id>" not found`. The shadcn `sonner` component is added (`pnpm dlx shadcn@latest add sonner`, without a `next-themes` dependency) and `<Toaster />` is mounted once in `src/App.tsx`.
8. `src/viewer/sample.ts` is updated so `Log in` has `id=login` and a `Text "Forgot password?" link-to=forgot`, and `Forgot password` has `id=forgot` and a `Text "Back to log in" link-to=login`; it still parses to an AST that passes `AstSchema`.
9. Viewer tests (`renderToStaticMarkup`, no new test setup) verify: linked nodes render `cursor-pointer`, `data-link-to` and `role="link"` and unlinked nodes do not; `findPageIndexById` for a known id, an unknown id and pages without ids. Click and toast behaviour are verified by testing the extracted logic as a pure function where needed (e.g. a `resolveLink(pages, id)` result of `{ index }` or `{ notFound }`), without a DOM.
10. `pnpm test` passes and `pnpm build` succeeds.
11. Updates `README.md` (syntax section and example: `id=` on `Page`, `link-to=` on `Box` and `Text`, clickable links in the preview, toast for unknown targets), and logs the implementation decisions in the Product Decisions or Technical Decisions of `/capabilities/trellis-ast/capability.md` and, for the viewer, `/capabilities/wire-frame-viewer/capability.md` (the `(planned)` entries are confirmed or amended by `CI-006 ... implementation` entries; old entries stay as history).
