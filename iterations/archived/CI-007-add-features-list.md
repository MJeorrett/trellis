# Iteration CI-007: Add Features List

**Target Capability:** `/capabilities/features/capability.md`

## User Story
As a Trellis user, I want a features page where I can see a list of features and create a new feature in a modal, backed by a mock API for now, on its own route separate from the wire frame demo, so that I can start managing the features of my product.

Read the `CI-007` entries in the Product Decisions, Technical Decisions and Data Dictionary of the target capability before starting, and the `CI-007 Route (planned)` entry in `/capabilities/wire-frame-viewer/capability.md`. They define the routes, the list states, the modal behaviour and validation, the mock API and the file layout.

## Acceptance Criteria
1. `react-router` is added with `pnpm add react-router`. `src/main.tsx` mounts a `BrowserRouter` and `src/App.tsx` defines the routes: `/features` (features page), `/wireframe-demo` (wire frame demo), `/` redirecting to `/features` and any unknown path redirecting to `/features`. `<Toaster />` is mounted once in `App.tsx`, outside the routes.
2. The current wire frame demo (source editor, `PageTabs` preview, sample, links and toasts) moves unchanged into `src/pages/wireframe-demo.tsx` and works at `/wireframe-demo`. The wire frame demo route does not show the features list or modal, and `/features` does not show the wire frame demo.
3. `public/_redirects` contains `/* /index.html 200` so deep links work on Netlify.
4. `src/features/schema.ts` exports `FeatureSchema` (`z.strictObject` with `id`, `name`, `description`, `createdAt`), `CreateFeatureInputSchema` (`z.strictObject` with `name`, `description`) and the derived `Feature` and `CreateFeatureInput` types. `name` must be non-empty after trimming; `description` may be `""`.
5. `src/features/api.ts` exports `listFeatures()` and `createFeature(input)` as described in `CI-007 Mock API implementation (planned)`: in-memory, seeded with a few features, async with a delay, returning copies, validating input, generating `id` and `createdAt`, and rejecting with an `Error` for invalid input. It also exports `resetMockFeatures()` and a way to set the delay to 0 for tests.
6. `src/pages/features.tsx` shows the page title, a `Create feature` button and the list of features (name and description, oldest first). It has no loading, empty or load-error states (see `CI-007 No list states (planned)`): the list is loaded once on mount and simply renders whatever `listFeatures()` returns. The mock API's simulated delay stays.
7. `Create feature` opens a modal (shadcn `dialog`) with a required `Name` input, an optional `Description` textarea, `Create` and `Cancel` buttons. The shadcn `dialog`, `input` and `label` components are added with `pnpm dlx shadcn@latest add dialog input label`. A blank name shows an inline message and does not call the API. Name and description are trimmed. On success the modal closes, the feature appears at the end of the list and a success toast is shown. On an API error the modal stays open, shows the error and keeps the entered values. `Cancel`, the close button and Escape close the modal and clear the entered values. `Create` is disabled while creating.
8. Tests (`pnpm test`, no new test setup; DOM-free as in the viewer): `src/features/schema.test.ts` covers valid and invalid features and inputs (blank name, whitespace name, unknown keys, empty description allowed). `src/features/api.test.ts` covers listing the seed, creating a feature (id, `createdAt`, trimmed values, appears in the next list), rejecting a blank name, returned copies not changing the store and `resetMockFeatures()`. The pure logic behind the form and list (validating the form values, appending a created feature) is tested as pure functions. `renderToStaticMarkup` tests verify the list renders names and descriptions and the `Create feature` button. A routing test (e.g. with `MemoryRouter` and `renderToStaticMarkup`) verifies that `/features` renders the features page, `/wireframe-demo` renders the wire frame demo, and `/` and an unknown path end up on the features page.
9. `pnpm test` passes, `pnpm typecheck` passes and `pnpm build` succeeds.
10. Updates `README.md` (routes `/features` and `/wireframe-demo`, the features page and the mock API note, and that the demo link and screenshot refer to `/wireframe-demo`), and logs the implementation decisions in the Product Decisions or Technical Decisions of `/capabilities/features/capability.md` and, for the route move, `/capabilities/wire-frame-viewer/capability.md` (the `(planned)` entries are confirmed or amended by `CI-007 ... implementation` entries; old entries stay as history).
